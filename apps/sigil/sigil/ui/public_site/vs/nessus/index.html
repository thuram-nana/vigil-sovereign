VIGIL vs. Nessus

Nessus is a mature, breadth-first vulnerability scanner — enormous plugin coverage for network and host CVEs and compliance checks. But a scanner flags; it rarely proves. VIGIL exploit-validates: it turns "this version looks vulnerable" into a signed FACT — or an honest LEAD — so your team stops drowning in maybe-findings. Use Nessus for inventory breadth; use VIGIL to prove what's actually exploitable.

Honesty bounds: VIGIL's host/CVE breadth is narrower than Nessus's plugin corpus today; its strength is proving exploitability, not enumerating every known signature. Cloud coverage is targeted (S3/IAM/achieved-state/K8s), not full CSPM.

Where Nessus wins

Sheer breadth of network/host vulnerability signatures, asset inventory, and compliance policy scanning, backed by a huge, long-maintained plugin feed. For a broad "what's out there" sweep, it's a workhorse.

Where VIGIL wins

It proves. A VIGIL FACT is an exploit that fired, signed and re-verifiable offline — zero false positives by construction — with real web/API/cloud exploitation depth, source + CI coverage, and a sovereign, BYO-LLM deployment.

FAQ

Should I drop my scanner?

No. Keep breadth tools for inventory. VIGIL's job is to cut the maybe-pile down to proven, exploitable issues — and it can take a scanner's lead as a starting point.

How is "zero false positives" possible?

A finding is only a FACT when a deterministic oracle fires over real target data. Everything else is labelled a LEAD. The model is never trusted for the verdict. See the proof model →
