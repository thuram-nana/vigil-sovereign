AI proposes, the oracle disposes

By the VIGIL team · Doctrine

Most "AI pentester" tools have the same quiet problem: a language model decides whether something is a vulnerability. Models are brilliant at proposing ideas and terrible at being trusted for a verdict — they hallucinate, they flatter, they round "maybe" up to "yes". Ship that to a security team and you've built a very fast way to generate false positives.

VIGIL is built on the opposite rule. The model is a navigator: it reads the target, forms hypotheses, and chooses what to try next. It is never the judge. A hypothesis becomes a FACT only when a deterministic oracle — code, not a model — fires over data a real, authorized target produced. If no oracle fires, the result is an honest LEAD: worth a look, never dressed up as confirmed.

What an oracle is

An oracle is a small, deterministic check with a yes/no answer about a specific observed effect: a value that could only appear if an injection executed; a state transition that could only happen if an access-control boundary was crossed; a differential across identities that proves one user reached another's object. It runs on the evidence, and it is reproducible.

Why this gives zero false positives by construction

If a FACT requires an oracle to fire, then a false positive would require a deterministic check to be wrong about an effect it directly observed — not a model to be over-confident. Some bug classes don't yet have a sound oracle; for those, VIGIL deliberately emits a LEAD rather than guess. The ratio of FACTs to LEADs is a number we'd rather keep honest than inflate.

The part we're proudest of: you don't have to trust us

Every FACT ships as a proof-carrying certificate — the inputs, the oracle, and the observed result. Hand that bundle to a third party and they re-run the check with zero VIGIL code installed and get the same verdict:

python3 -m framework.v2 verify ./evidence/<finding>.json

That one property — a finding that re-proves itself, offline, to a skeptic — is the whole thesis. It's why a VIGIL report shrinks your triage queue instead of growing it, and it's the bar we hold every new detector to.
