# CRUCIBLE benchmark — methodology (reproducible)

This is a **runnable methodology**, not a results snapshot. Everything below can be
re-run by anyone with this repository; the numbers a run produces on your host are
written to committed, machine-readable artifacts you can diff against ours. The
claim we stake credibility on is narrow and testable: **CRUCIBLE reports only
oracle-confirmed findings, so its false-positive rate is ~zero — including on real
production software that has no planted bugs.** The benchmark exists to keep us
honest about that.

## TL;DR — rerun it

```bash
# CI spine: the labelled in-process app, no Docker, no external tools.
make gate                       # exit 1 on ANY CRUCIBLE regression (new FP / newly-missed / precision drop)
make bench                      # CRUCIBLE vs whatever incumbents are installed -> scoreboard + report

# Reproduce the committed public scoreboard + machine-readable snapshot:
python3 -m framework.v2 benchmark \
    --report framework/v2/docs/benchmark-scoreboard.md \
    --json   framework/v2/docs/benchmark-results.json

# Operator: the dockerized multi-app corpus (needs Docker).
make bench-corpus               # runs eval/corpus_apps/*, skips heavy/unavailable with reasons
python3 -m framework.v2 benchmark --corpus --apps dvwa,juice-shop --incumbents
```

Committed artifacts (regenerated by the commands above):
- `framework/v2/docs/benchmark-results.json` — machine-readable per-tool accuracy + cost, incumbent versions, exact invocations.
- `framework/v2/docs/benchmark-scoreboard.md` — the rendered public scoreboard.
- `framework/v2/eval/baselines/benchmark-app.json` — the committed baseline the gate enforces.

## The three-tier corpus

Credibility needs breadth, not one hand-picked app. The corpus spans three roles,
each answering a different question a professional actually asks:

| Tier | Question | Ground truth | Apps |
|------|----------|--------------|------|
| **Labelled** | Precision/recall vs a NEUTRAL standard | the suite's OWN published labels | OWASP Benchmark (1.2) |
| **Deliberately-vulnerable** | Does it find real, known bugs? | curated (disclosed caveat) | Juice Shop, DVWA, VAmPI, DVGA, Mutillidae, WebGoat(+WebWolf) |
| **Real-enterprise** | FP rate + discovery on production software with NO planted bugs | none (every confirmed finding is scrutinised) | WordPress, Drupal, Keycloak, GitLab CE, Mattermost |

Each app is one JSON descriptor under `eval/corpus_apps/` — how to stand it up in
Docker, when it is healthy, where to scan, and what its ground truth is. The
descriptors for prebuilt public images are honest about being **unverified in the
build environment** (this sandbox cannot pull from Docker Hub); the operator runs them.

### Real historical CVEs (runs even without registry access)

The most persuasive rebuttal to "you designed the benchmark yourself" is a **known
historical vulnerability in a real, widely-used package** — and this tier runs here
despite the registry block. Each app under `eval/corpus_apps/_cve/` pins a real npm
package at a version with a **published CVE** and exposes that package's documented
flaw. The vulnerable dependency comes from the npm registry (reachable where Docker
Hub is not), so `_cve/build.sh` builds the app on the host and copies it into the
cached `node` base — no prebuilt-image pull. The vulnerability is in the *package*, not
in harness code.

| app | package | CVE | class | verified result |
|-----|---------|-----|-------|-----------------|
| `cve-st-2014-3744` | `st@0.2.4` | CVE-2014-3744 | path traversal | **tp=1, fp=0, precision 1.000** — CRUCIBLE injects an encoded `../` into a path segment, `st` serves `/etc/passwd`, and the finding is confirmed on the `root:x:0:0:` file-content signature (a real file read, not a reflected path) |

```bash
bash framework/v2/eval/corpus_apps/_cve/build.sh
python3 -m framework.v2 benchmark --corpus --apps cve-st-2014-3744 --no-incumbents
```

This is the same crawl → check → oracle → scoreboard pipeline as the in-process app,
now confirming a **real, cited npm CVE** end-to-end with zero false positives. The
tier is extensible — drop another pinned-CVE app under `_cve/` and add its descriptor.

### Four measured dimensions

A Scoreboard says how *accurate* a tool is; that is not the whole story. Every run
also records **cost** (`RunMetrics`): wall-clock, active requests issued, best-effort
peak RSS, and crawl breadth. Numbers a tool cannot honestly report (an incumbent's
internal request count) are `null`, never a fabricated 0.

- **precision / recall** — on labelled tiers, against neutral truth.
- **false-positive count** — on the real-enterprise tier; the zero-FP thesis.
- **discovery / coverage** — pages crawled, requests found.
- **performance** — time, request budget, RSS — vs incumbents.

## Ground truth — how it is established

- **Neutral (labelled tier).** The OWASP Benchmark ships its own
  `expectedresults-1.2.csv`; `eval/owasp_benchmark.py` loads it directly. Nobody
  scoring against it wrote the labels, so the numbers are not contestable on fairness
  grounds. It restricts to the **DAST-reachable categories** (injection, traversal,
  XSS) and *excludes* the code-level categories (weak crypto/hash/randomness,
  insecure-cookie flags, trust-boundary) a black-box HTTP scanner structurally cannot
  reach — a disclosed, standard restriction for DAST benchmarking.
- **Curated (vulnerable tier).** For deliberately-vulnerable apps we author a small
  manifest of high-confidence, stable, well-documented bug locations. **Caveat,
  disclosed:** these labels are *our* curation — co-designed with the tool — and each
  descriptor's `notes` says so and says they should be verified against the pinned
  image. This is why the labelled and real-enterprise tiers exist: they are not
  co-designed.
- **None (real-enterprise tier).** No manifest. The metric is the *count of confirmed
  findings* (ideally ~zero on well-maintained software) plus discovery + performance.
  A confirmed finding here is a real, oracle-carrying result the operator adjudicates
  — we never force "zero findings".

## The matcher

A produced finding matches an expected one iff their **bug-class families** are equal
AND their **locations correspond** (same path+parameter). Greedy one-to-one: each
expected bug is claimed once. A produced finding matching nothing is a false positive
**by construction** — that is what a complete manifest buys. The class-key collapses
CRUCIBLE's fine classes to the label's granularity symmetrically (`boolean_sqli` /
`error_based_sqli` satisfy an `sqli` label; `lfi` satisfies `path_traversal`), so it
can only ever merge same-family labels, never inflate a match. See
`eval/validation.py:score` and `eval/owasp_benchmark.py:owasp_class_key`.

## Incumbents — versions and exact invocations

Incumbents are shelled out with fixed arguments; an incumbent not installed is
*skipped, not failed*. Versions are captured into `benchmark-results.json` at
generation time. On the host that produced the committed snapshot:

| tool | version | invocation |
|------|---------|------------|
| sqlmap | 1.10.6#stable | `sqlmap -u <url> --batch` |
| wapiti | 3.2.10 | `wapiti -u <url> -f json -o <file>` |
| nikto | 2.6.0 (LW 2.5) | `nikto -h <url> -Format json -output <file>` |
| nuclei | v3.10.0 (installed; not one of the three scored incumbents) | `nuclei -u <url> -jsonl -silent` |
| ZAP | absent here | `zap.sh -cmd -quickurl <url> -quickout <file>` |

The three scored incumbents are sqlmap, Wapiti, and Nikto. Nuclei is installed on this
host but is *not* one of the three the comparative runner drives (its version is probed
into the JSON as reproducibility metadata only). Every version string above is captured
into `benchmark-results.json` / `benchmark-comparative.json` at generation time.

Adapters live in `eval/adapters.py` + `eval/adapters_ext.py`.

## Current public scoreboard (in-process labelled app)

The self-contained labelled app has **11 planted bugs** (reflected XSS, boolean-blind
SQLi, error-based SQLi, open redirect, path traversal, SSTI, host-header injection,
CORS-with-credentials, and three exposures: `.git/config`, `.env`, Spring
`/actuator/env`) plus **8 safe controls** (`/users/safe`, `/locations`, `/lookup`,
`/profile`, `/api/health`, `/download`, `/greeting`, `/support`) that must never be
flagged — `/users/safe` is the parameterised twin of the boolean-SQLi endpoint, and
`/locations` + `/lookup` are the discriminating no-database controls. From the committed
`benchmark-comparative.json` (this host — sqlmap 1.10.6, Wapiti 3.2.10, Nikto 2.6.0):

> **Re-baseline note.** The signed snapshot above is the run that produced it and is
> left byte-intact. Its corpus modelled boolean-blind SQLi at `/users?name` with two
> REGEXES that only understand literal equality: of the seven syntactically-varied
> always-TRUE/always-FALSE clause shapes a sound detector sends, 1 of 7 partitioned it,
> so the only detector it rewarded was the bare benign-vs-payload differential — the one
> measured minting `boolean_sqli` at rate 1.0 against targets with **no database**.
> `/users?name` is now a real sqlite3 engine with a concatenated `WHERE` clause (**7 of 7**
> shapes partition), the gate scores it with the sound SPRT `BooleanInferenceCheck` — which is
> now `DEFAULT_CHECKS`' own `BOOLEAN_SQLI_SPRT`, the detector an operator's default scan runs,
> not a benchmark-local copy — and
> `/users/safe` is the parameterised twin that must never fire (**0 of 7**).
>
> The corpus additionally ships two **discriminating** no-database controls, because the
> parameterised twin alone could not pin the soundness this change exists for: a
> payload-SHAPE reader does not fire on the twin either, so reverting the whole detector
> still passed the gate. `/locations?city` (a CRS-942130 tautology WAF rule over a static
> page) and `/lookup?term` (strict input validation over a static page) are surfaces where
> the shape is present and the injection is not — a bare differential **sees a channel on
> both** (measured) while the sound detector **refuses on both** (measured). Reverting the
> detector content now fails the gate: `10 tp / 0 fp / 1 fn`, recall 0.909.
>
> Accuracy never moved — the current gate row is still **11 / 0 / 0**, and the signed
> `recall-accuracy-core.json` still reproduces byte-identically — but the request budget
> was deliberately re-baselined **1069 -> 1544 -> 1831**: stage 1 was +114 twin surface,
> -320 dropped library boolean differentials, +682 SPRT; stage 2 was +1 (the
> file-signature check's new benign control, spent only where it fires) and +288 (the two
> discriminating controls, 144 sends each). `test_gate_invariants.py` carries the
> line-by-line accounting and the offset rule that relates counted to reported requests.
>
> **What the sound detector costs, and what it covers.** An attribution step is not free:
> the SPRT spends a determinism pre-gate (8 identical sends) plus 4x7 = 28 probes per round and
> decides in two rounds, so **+62 requests per insertion point** against the 2 the differential
> spent. On a 6-query-param endpoint that is **66 -> 438 requests (6.6x)**; `--targeted` only
> reaches 349. The gate's own `time_s` went 11.55 -> 30.04. Coverage is **clause family 0 only**

> recorded in `docs/capability-matrix/evidence-branches.json` rather than left implicit.
>
> **Per-class outcome of making the truth-value classes BOOLEAN_INFERENCE-only** (measured, not
> inferred): `boolean_sqli` **fixed** — the default path has a sound producer again.
> `ldap_injection` / `xpath_injection` **no loss** — their error-signature entries were driven
> end-to-end through `compile_entry` -> `ErrorSignatureCheck.probe` -> `confirm_finding` and

> `error_signature.strix_redrive`. **`auth_bypass` has no detector on any path** — and no
> evidence branch has ever claimed one, so nothing in the capability matrix overclaims.
>
> **Stale unsigned renderings, named rather than silently left.** Two files in this
> directory still say "five SAFE endpoints" and quote 1069: `benchmark-scoreboard.md`
> (lines 8, 56) and `benchmark-comparative.md` (lines 8, 59). Neither carries a

> `09-the-screens.md:1346,1360`, `VIGIL-EXPLAINED.md:1626,7292,17011,17025`).

Read the **fp column**, not the tp column: it is the unambiguous one. CRUCIBLE's 0
is the differentiator. The recall/precision of incumbents is depressed partly by
label-vocabulary and location-granularity mismatches (a generic "SQL Injection" vs
`error_based_sqli`, a host-level message vs a `request:<check>` token) — the raw
per-tool finding lists tell the fuller story; the FP column does not have that excuse.
`n/r` = the tool does not report that number.

**This zero-FP result now holds on realistic reflecting endpoints too.** An earlier
version of CRUCIBLE confirmed SSTI / path-traversal / error-based SQLi on *mere
payload reflection*; on any app with a reflecting endpoint (a search box) that
produced false positives, and the in-process app only avoided it by reflecting solely
markup-shaped input. Those checks now require **evidence** — the server must have
*evaluated* the expression, *read* the file, or *emitted a datastore error* — and a
regression guard forbids reintroducing a reflection oracle for a non-XSS class
(`test_library.py:test_no_reflection_oracle_for_injection_classes`).

## The regression gate

`make gate` runs the labelled app and fails on any CRUCIBLE regression vs
`eval/baselines/benchmark-app.json`: a **new false positive**, a **newly-missed
finding**, or a **precision drop**. It is asymmetric — fewer FPs / more TPs are
improvements, not failures (refresh the baseline with `make baseline`). It needs no
Docker and no external tools, so it runs in any CI. The dockerized corpus has the
same gate (`make gate-corpus`) against a baseline the operator snapshots for the apps
they can stand up.

## Honest limitations

- **Curated manifests are co-designed** with CRUCIBLE. That is why the neutral
  (OWASP Benchmark) and no-manifest (real-enterprise FP) tiers carry the credibility
  weight; the curated tier is a convenience, disclosed per app.
- **Heavy apps** (OWASP Benchmark build, GitLab CE, Mattermost) are RAM-heavy and are
  never auto-launched; they are operator-run. A skipped app is reported with a reason,
  never counted as passed.
- **SPA / authenticated apps** (Juice Shop, WebGoat, GitLab) need a browser pass or a
  login recipe for full coverage; each descriptor discloses this, and un-driven
  endpoints are listed for recall accounting rather than over-claimed.
- **This environment has no network** to pull images, so only the in-process app and
  a locally-built smoke container were run here; the external corpus is shipped as
  descriptors for an operator to run. No numbers are fabricated for an app that did
  not actually run.
