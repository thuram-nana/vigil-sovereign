After an exhaustive gap/limitation audit (categories A–M — see the audit in `~/.claude/plans/parsed-popping-lemur.md` history), the operator asked to **deploy 13 specialised lead-agents, each with its own sub-agent swarm, working A→M simultaneously**. Plan approved (ExitPlanMode). **Operator decisions:** L → gated Tier-3 *validation* slice (doctrine-max; still NO evasion/C2/persistence/cred-suites/identity-rotation); G → optional extras default-absent; scope → first-slice+roadmap. Guardrails: every WS additive/default-OFF, `make gate` byte-identical (9/0/0/853/9), doctrine hard-exclusions never built.

**WHAT HAPPENED — a mid-run API OUTAGE.** All 13 leads launched (isolation:worktree); the 4 sub-swarm leads (C/D/I/K) spawned their own sub-agents (~30+ agents total). Then a broad API outage hit: agents died with "Connection closed mid-response" / stalled on the 600s stream watchdog. **Root-cause pattern: the agents WROTE COMPLETE, WORKING CODE, then their long final test-run stream timed out** — the code survived, only the agent's own validation step died. **My own short interactive Bash/Edit calls kept landing** even while the long agent streams failed — so the recovery was: I drove validate+merge MYSELF, not via the fleet.

**RECOVERY (the playbook that worked):** (1) do NOT remove any worktree (uncommitted WIP is safe on disk). (2) `git checkout -- .dryrun/` then commit each worktree's WIP to its branch = a durable checkpoint (survives worktree auto-clean). (3) triage each branch: import + targeted tests + `git show`/diff. (4) merge the green, additive, doctrine-scanned ones ONE AT A TIME with `make gate` byte-identical after each; resolve the additive-append enum/registry conflicts as unions (keep-both). (5) prune merged worktrees, keep deferred ones.

**GOTCHAS:** (a) **Nested sub-swarms are FRAGILE** — WS-C's lead delegated to sub-agents + committed nothing itself; when it stalled, its UNCHANGED lead worktree auto-cleaned → its work was nearly lost (recovered because sub-agents wrote to the shared checkout / their own branches). **Prefer ONE agent doing its sub-tasks sequentially over a lead-that-only-delegates.** (b) A sub-agent whose worktree was deleted **fell back to writing UNCOMMITTED into the shared `main` checkout** — check `git status` on main for contamination after such failures (WS-C surface-3's client-side checks landed there; I verified + committed them). (c) `git diff main..<branch>` shows PHANTOM DELETIONS when the branch is based on an older main (files added by other merges look "deleted"); the 3-way MERGE is correct — trust the merge's "N files changed", not the diffstat. (d) `world.node_count` is a `@property` not a method — WS-A's only bug was `node_count()` (TypeError: 'int' not callable) in 3 spots.
