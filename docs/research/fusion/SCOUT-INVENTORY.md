## agentic/ — LangGraph ReAct core agent: state model, phase machine (informational/exploitation/post_exploitation), graph wiring, per-request context propagation, and cross-service signed-context tags

- **Repo:** samugit83/redamon  |  **Priority:** high
- **Files read:** https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/state.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/agent_context.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/redamon_ctx.py

**What it does.** orchestrator.py builds a langgraph StateGraph(AgentState) running an offensive-security ReAct agent. ~14 nodes: initialize, think (the LLM reasoning step emitting ONE structured LLMDecision whose ActionType is use_tool/plan_tools/transition_phase/complete/ask_user/deploy_fireteam/switch_skill), execute_tool, execute_plan (parallel wave), await/process_approval, await/process_question, await/process_tool_confirmation, deploy_fireteam, fireteam_collect, process_fireteam_confirmation, generate_response. Conditional routers (_route_after_initialize, _route_after_think, _route_after_approval, _route_after_answer, _route_after_fireteam_collect, _route_after_tool_confirmation) branch on the decision. START->initialize; tool nodes unconditionally loop back to think (the ReAct cycle); await_* nodes edge to END to SUSPEND the graph. Phase machine escalates informational->exploitation->post_exploitation: think requests the transition, a risky boundary sets phase_transition_pending + awaiting_user_approval so the router parks at await_approval(END) until resume_after_approval_with_streaming() feeds an ApprovalDecision(approve/modify/abort) back into the checkpointed state. Tools run through a PhaseAwareToolExecutor that blocks phase-inappropriate tools; dangerous tools park at await_tool_confirmation. Checkpointer is MemorySaver or AsyncPostgresSaver; runs stream via astream(stream_mode='values') + a per-session callback (on_thinking/on_tool_output_chunk/on_phase_update/on_approval_request). deploy_fireteam spawns a 1-8 member parallel sub-graph (FireteamMemberState) whose dangerous-tool decisions escalate back to the parent for confirmation. state.py defines the ~80-field AgentState TypedDict, FireteamMemberState, ~30 pydantic models (LLMDecision, PhaseTransitionDecision, ToolPlan/ToolPlanStep, FireteamPlan/FireteamMemberSpec/FireteamMemberResult, OutputAnalysisInline, ProductivityVerdict, DeepThinkResult/CompetingHypothesis, ChainFindingExtract, TargetInfo w/ merge_from, TodoItem, ExecutionStep, ConversationObjective/ObjectiveOutcome, ToolConfirmationRequest, UserQuestionRequest), the enums (Phase, TodoStatus, Priority, ApprovalDecision, QuestionFormat, ActionType, FireteamMemberStatus, KNOWN_ATTACK_PATHS), the add_messages reducer, attack-chain memory (chain_findings/failures/decisions/waves), multi-objective tracking, productivity-scoring v2 loop detection, and format_* prompt renderers. agent_context.py = ContextVars (current_user_id/project_id/session_id/current_phase/current_graph_view_cypher) so tools read tenant+phase identity from any stack depth without threading args (deliberately import-light to keep fs/job/offload modules free of langchain/MCP/neo4j). redamon_ctx.py = HMAC-SHA256 signed capability tags for cross-service context (source-selected key recon-vs-agent, whitelisted canonical-JSON fields, base64url, constant-time compare, fail-closed verify_tag).

**Novel ideas:**
- Phase-aware tool executor + human-in-the-loop phase-transition gate (informational/exploitation/post_exploitation) with graph-suspend-to-END then resume-from-checkpoint — mirrors the pentest kill-chain escalation and is a natural fit for WARDEN tiers
- Productivity-scoring v2 loop detection where OBSERVED state-delta overrides the LLM's self-reported new_information_gained (downgrades dishonest 'progress' to no_progress) — prove-don't-guess applied to the agent's own honesty; plus tested_axes semantic ledger to catch slow loops spanning many iterations, and paraphrase-rejection of Deep Think plans (_previous_priority_order) and a diagnostic-progress streak cap so debugging a dead approach can't mask a stall
- Deep Think forces >=2 CompetingHypothesis entries — mandatory articulation of alternative explanations before committing, same spirit as CRUCIBLE critics
- 'Fireteam' parallel multi-agent wave (1-8 members, own FireteamMemberState) with dangerous-tool confirmation ESCALATED back to the parent graph (fireteam_collect -> await_tool_confirmation) rather than decided locally
- Single structured LLMDecision object routes all 7 action types through one schema — one router (_route_after_think) drives the entire ReAct branch
- redamon_ctx signed capability tag: source-selected key (recon vs agent), whitelisted canonical-JSON fields, base64url, constant-time compare, fail-closed — a clean cross-service provenance token (scanner->agent) that VIGIL can upgrade to Ed25519
- Persistent cross-session attack-chain memory (findings/failures/decisions/waves) deduped by normalized title + severity, injected into prompts (format_prior_chains) — the attack-chain graph memory VIGIL lacks
- ContextVars for tenant+phase propagation to tools without arg-threading, deliberately kept import-light so fs/job/offload modules don't drag in langchain/MCP/neo4j
- LLM-output-drift tolerance without re-prompting: _coerce_priority (severity synonyms -> canonical Priority) and is_valid_attack_path_value (builtin | user_skill:* | *-unclassified)

**VIGIL gap.** VIGIL has the sovereign provable core (Ed25519 spine, WARDEN A0-A3, oracle-confirmed FACT vs lead, conjunctive gate, egress gate) but LACKS the agent scaffolding this repo is entirely about: (1) a mature LangGraph ReAct loop with a single structured LLMDecision routing 7 action types; (2) an explicit offensive PHASE state machine (informational->exploitation->post_exploitation) with per-phase tool gating (PhaseAwareToolExecutor); (3) human-in-the-loop interrupt/resume for phase transitions AND dangerous-tool confirmations (graph suspends to END, resumes from checkpoint); (4) persistent attack-chain graph memory (findings/failures/decisions/waves) carried across iterations and sessions and injected into prompts (format_prior_chains/format_chain_context); (5) parallel multi-agent 'fireteam' waves with confirmation-escalation back to the parent; (6) productivity/loop-detection that trusts OBSERVED state-delta over the LLM's self-report; (7) multi-objective engagement tracking; (8) rich LLM-output-drift tolerance (_coerce_priority, is_valid_attack_path_value). VIGIL's memory notes explicitly list these as its gaps: attack-chain graph memory, mature agent fs/job tooling, breadth of recon, rich LLM-safety guards.

**Integration (through the provable layer).** Fuse the SHAPE, re-plumb every action edge through VIGIL's sovereign core; do NOT graft the executor as-is. Concrete mapping: (a) RedAmon's think 'proposes' and execute_tool 'acts' — this IS VIGIL's LLM-proposes/oracle-confirms split. Route every execute_tool/execute_plan result into a CRUCIBLE deterministic oracle; oracle-confirmed => signed FACT appended to the Ed25519 hash-chain spine, otherwise labelled lead. Critically, LLMDecision.output_analysis.exploit_succeeded / OutputAnalysisInline are LLM CLAIMS and must be treated as proposals only — never persisted as findings without oracle re-execution. (b) Replace PhaseAwareToolExecutor's phase gate with WARDEN tiers: informational~A0/A1, exploitation~A2, post_exploitation~A3; the await_tool_confirmation / await_approval interrupts become the human-approval leg of VIGIL's conjunctive gate (authority ∧ tier ∧ m-of-n threshold), so a phase escalation or destructive tool needs signed authority + tier + threshold, not just an ApprovalDecision. (c) Replace/anchor the checkpointer: MemorySaver/Postgres state is MUTABLE and un-provable — snapshot AgentState + execution_trace into the append-only signed spine so the whole run is offline-verifiable and can mint a SCITT/OpenVEX cert; keep Postgres only as a cache. (d) Adopt redamon_ctx signed tags as an inner capability token but upgrade recon->agent trust to Ed25519 and chain it into the spine (HMAC ok as a fast inner check). (e) tested_axes + ProductivityVerdict (observed-state-delta beats self-report) and DeepThink's mandatory >=2 competing hypotheses map directly onto VIGIL/CRUCIBLE's metacog critics — port them as critic modules. (f) fireteam members each run under their own tier-scoped WARDEN context; every escalation bubbles through the gate, and every member action still confirms via oracle. Effort: S = adopt agent_context ContextVars + redamon_ctx signed-tag pattern + the enums/LLMDecision schema; M = adopt the state model + phase machine + loop-detection/critics as VIGIL's agent core; L = the full graph incl. fireteam parallelism, MCP tools, KB, and spine-anchored checkpointing. MAIN RISK: naive port BYPASSES the sovereign core — RedAmon's think node can transition phase and fire dangerous tools subject only to LLM+optional-human approval, and OutputAnalysis asserts exploits without proof. Every action-bearing edge (execute_tool, execute_plan, deploy_fireteam, transition_phase, switch_skill) MUST be re-routed through oracle-confirm + conjunctive gate + egress gate, or VIGIL loses its provability guarantee.

## Agentic ReAct orchestrator — LangGraph node graph (think → execute-tool / execute-plan → generate-response) + phase gating + attack-chain graph memory + planner meta-cognition

- **Repo:** samugit83/redamon  |  **Priority:** high
- **Files read:** https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/think_node.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/execute_plan_node.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/execute_tool_node.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/generate_response_node.py, https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/phase.py

**What it does.** A LangGraph-based autonomous pentest orchestrator implemented as a small ReAct node graph. `think_node` is the brain: it assembles a large, layered system prompt (base ReAct + deep-think + scope-guardrail + RoE + stealth + tiered productivity hints + pending-output-analysis), calls the LLM once, and parses a single `LLMDecision` whose `.action` field (use_tool | plan_tools | transition_phase | switch_skill | deploy_fireteam | ask_user | complete) routes the whole graph. Crucially it also folds the PREVIOUS tool's output back in the SAME call: the pending step's output is injected via `PENDING_OUTPUT_ANALYSIS_SECTION` and the LLM returns `output_analysis`, which populates `chain_findings_memory`/`chain_failures_memory`, the `execution_trace`, the merged `TargetInfo`, and a Neo4j chain graph (ChainStep→ChainFinding/ChainFailure with prev-step linkage). `execute_tool_node` runs a single tool with a cancellable per-tool Stop, a recon-budget gate, an RoE severity-phase cap, embedded-error detection (`_detect_embedded_tool_error` flips MCP success=True bodies that actually carry a Playwright/timeout error to failure), `classify_error_class`, and MSF/netcat listener-session detection. `execute_plan_node` runs a parallel 'wave' of tools via `asyncio.gather` under a semaphore (`PLAN_MAX_PARALLEL_TOOLS`) with `_validate_plan_mutex_groups` (singleton tools can't run twice) and `_check_roe_blocked`. `phase.py` LLM-classifies the attack path (`classify_attack_path` → Pydantic `AttackPathClassification`, retry+backoff, safe default cve_exploit/informational) and gates phase moves (`determine_phase_for_new_objective`: auto-downgrade to informational, require approval to escalate). `generate_response_node` emits an adaptive final answer at one of three tiers (conversational | summary | full_report).

**Key abstractions (reusable):**
- Nodes: think_node(state, config, *, llm, guidance_queues, neo4j_creds, streaming_callbacks, graph_view_cyphers), execute_tool_node(..., *, tool_executor, streaming_callbacks, session_manager_base, graph_view_cyphers), execute_plan_node(..., same kwargs), generate_response_node(..., *, llm, streaming_callbacks, neo4j_creds)
- phase.py: classify_attack_path(llm, objective, max_retries=3)->Tuple; determine_phase_for_new_objective(required_phase, current_phase); Pydantic AttackPathClassification (attack_path_type, required_phase, target_host/port/cves, confidence, detected_service)
- LLMDecision with single dispatch field .action ∈ {use_tool, plan_tools, transition_phase, switch_skill, deploy_fireteam, ask_user, complete}; sub-objects tool_plan/ToolWave, phase_transition, skill_switch, fireteam_plan, user_question, output_analysis, updated_todo_list, need_deep_think
- AgentState keys: _current_step, _current_plan, execution_trace, chain_findings_memory, chain_failures_memory, chain_decisions_memory, chain_waves_memory, tested_axes, target_info(TargetInfo), current_phase, phase_history, phase_transition_pending, awaiting_user_approval, _iterations_since_state_grew, _diagnostic_progress_streak, _deep_think_cooldown_until, _previous_priority_order, _need_deep_think, _last_chain_step_id
- Inline result-folding: PENDING_OUTPUT_ANALYSIS_SECTION / PENDING_PLAN_OUTPUTS_SECTION inject prior tool output into the same think call; OutputAnalysis returns interpretation, actionable_findings, chain_findings, exploit_succeeded/details, extracted_info, productivity
- Meta-cognition: compute_productivity_score, tier_for_score(hint=3/deepthink=5/pivot=7/block=9), audit_productivity_claim, downgrade_verdict_to_no_progress, detect_state_growth, detect_diagnostic_progress, update_stall_counters, extract_axis/axis_key/record_axis_attempt, priority_order_jaccard (DEEP_THINK_NOVELTY_JACCARD_MAX=0.6), detect_uniform_response_anomaly, build_productivity_audit_section
- Deep-think: DEEP_THINK_PROMPT/DEEP_THINK_SECTION → DeepThinkResult(situation_assessment, competing_hypotheses, attack_vectors_identified, recommended_approach, priority_order, risks_and_mitigations); cooldown with _critical_override/_stall_override
- execute_tool_node: _detect_embedded_tool_error + _EMBEDDED_ERROR_PATTERNS regex list, classify_error_class(success, tool_output, error_message, duration_ms, tool_name), recon-budget gate (RECON_MAX_INFORMATIONAL_ITERS + RECON_DISCOVERY_TOOLS set), RoE PHASE_ORDER severity cap, cancellable _tool_task with current_task().cancelling() inner-vs-outer cancel test, MSF 'session N opened' regex + nc/socat listener detection
- execute_plan_node: _validate_plan_mutex_groups (TOOL_MUTEX_GROUPS), _check_roe_blocked (CATEGORY_TOOL_MAP, ROE_FORBIDDEN_*), _execute_single_step, _bounded_step closure under asyncio.Semaphore(PLAN_MAX_PARALLEL_TOOLS), asyncio.gather(return_exceptions=True), wave_id=f'wave-{iter}-{uuid4hex}'
- Chain graph API: chain_graph.sync_record_step, fire_record_finding, fire_record_failure, fire_record_exploit_success, fire_update_chain_status (ChainStep/ChainFinding/ChainFailure nodes, prev_step_id linkage, get_agent_context for agent_id/source_agent/fireteam_id)
- Response tiers: determine_response_tier → CONVERSATIONAL_RESPONSE_PROMPT / SUMMARY_RESPONSE_PROMPT / FINAL_REPORT_PROMPT; prompt caching via CACHE_PREFIX_END_MARKER + Anthropic ephemeral cache_control split; fireteam sub-agent spawning gated to FIRETEAM_ALLOWED_PHASES

**Novel ideas:**
- Single-call result-folding: the previous tool's output is analyzed in the SAME think LLM call that picks the next action (output_analysis returned inline), collapsing observe+orient+decide into one turn and directly populating chain memory — no separate reflection node.
- Self-claim HONESTY AUDIT: audit_productivity_claim cross-checks the LLM's own 'I made progress' verdict against measured state delta (findings_grew, extracted_info), and downgrade_verdict_to_no_progress overrides an over-optimistic planner — a lightweight anti-hallucination check applied to the AGENT'S reasoning, not just tool output. Directly kin to VIGIL's veracity firewall.
- Embedded-error detection: MCP/tool wrappers routinely return success=True with a real failure buried in the body (Playwright 'Page.goto: Timeout'); regex-scanning the head of the output and flipping success→False so a ChainFailure gets written and the agent LEARNS instead of retrying the same failing pattern.
- Productivity scoring → tiered prompt injection → deep-think escalation, with a Jaccard novelty guard on the deep-think's priority_order so the strategic re-plan can't just restate the same plan, plus cooldowns overridden by critical-score/stall — a full anti-stagnation control loop.
- Recon-budget COMMIT gate: after N informational iterations, discovery/scanning tools are hard-disabled to force switch_skill→transition_phase, breaking the 'scan forever' failure mode with a concrete tool-family denylist.
- Axis ledger (tested_axes + extract_axis/axis_key/record_axis_attempt) records the (tool,param) axis and verdict of every attempt so the planner can be told which hypothesis classes are exhausted.
- error_class taxonomy that separates a shell-quoting glitch from a real 4xx from a 5xx-that-crashed-in-3ms (duration-aware), surfaced back to the LLM so it sees WHICH kind of failure occurred.
- Parallel tool 'waves' with mutex/singleton groups (two metasploit_console steps can't run concurrently) under a semaphore, plus per-tool cancellable Stop that distinguishes an inner per-tool cancel from an outer run-teardown via current_task().cancelling().
- Attack-chain persisted as a graph (Neo4j ChainStep→ChainFinding/ChainFailure with prev-step edges and per-agent/fireteam attribution) — durable, queryable attack-chain memory across sessions.
- Phase gate policy 'auto-downgrade free, escalation needs approval' + LLM attack-path classifier with Pydantic validation, retry/backoff, and a safe recon-first default.

**VIGIL gap.** VIGIL has a signed spine, WARDEN tiers, oracle-confirmed FACTs, and gates, but lacks the autonomous agent machinery that drives them: (1) attack-chain GRAPH memory — redamon's Neo4j ChainStep/ChainFinding/ChainFailure with prev-step linkage and per-agent/fireteam attribution is exactly the attack-chain graph memory VIGIL is noted to lack; (2) a mature ReAct node-graph with a single-decision action dispatch and inline result-folding; (3) planner meta-cognition / rich LLM-safety guards — continuous productivity scoring (`compute_productivity_score`→`tier_for_score` green/yellow/red/critical), deep-think strategic re-evaluation with Jaccard novelty guard and cooldowns, a self-claim HONESTY AUDIT (`audit_productivity_claim`→`downgrade_verdict_to_no_progress`) that checks the LLM's own 'I made progress' claim against real state delta, stall/axis ledgers (`tested_axes`, `_iterations_since_state_grew`), a recon-budget commit-gate, and embedded-error + error-class detection; (4) chain memory (`chain_findings_memory`/`chain_failures_memory`/`chain_decisions_memory`) fed back into the prompt so the agent stops repeating failed patterns; (5) mature agent fs/job tooling (workspace layout notes/ tool-outputs/ jobs/ uploads/, streaming per-tool cancellation); (6) breadth of recon/exploit tool dispatch and parallel tool waves with mutex groups.

**Integration (through the provable layer).** See integration field above — fuse via oracle interposition (LLM proposes → oracle confirms → signed FACT), WARDEN tier ∧ conjunctive-gate on every action-dispatch edge, phase→tier mapping with signed m-of-n approvals, and Neo4j chain graph as a spine projection; effort L overall (S/M for individually liftable guards: embedded-error S, error-class S, recon-budget S, meta-cognition M, honesty-audit→oracle M, graph-as-projection M); main risk = letting LLM-self-asserted findings/honesty-audit reach the spine as FACTs (breaks oracle-sole-authority) and a dual-source-of-truth Neo4j graph.

## Fireteam / Scatter-Gather ReAct: governed parallel specialist sub-agents (fan-out/fan-in, bounded recursion, per-member guardrails, human-in-the-loop confirmation)

- **Repo:** samugit83/redamon (agentic/orchestrator_helpers)  |  **Priority:** high
- **Files read:** https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/fireteam_member_graph.py (full), https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/fireteam_deploy_node.py (structured outline; fetcher declined verbatim, all constants/fn-names/control-flow extracted), https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/fireteam_member_think_node.py (structured outline; fetcher declined verbatim, all constants/fn-names/control-flow extracted), https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/nodes/fireteam_collect_node.py (full), https://raw.githubusercontent.com/samugit83/redamon/master/agentic/orchestrator_helpers/fireteam_confirmation_registry.py (full)

**What it does.** A LangGraph-based "fireteam" subsystem that lets a root ReAct agent spawn a wave of specialist sub-agents, run them concurrently under hard caps, and merge their results back into parent state. (1) fireteam_member_graph.py compiles a per-member StateGraph over FireteamMemberState with nodes think/execute_tool/execute_plan/await_confirmation/complete and deterministic conditional-edge routers; the iteration cap is enforced in the router (current_iter > max_iter -> complete), not by the LLM. (2) fireteam_deploy_node.py is the fan-out: it validates the member plan (cap of FIRETEAM_MAX_MEMBERS=5, mutex-group check so two members can't both claim a singleton tool like metasploit), spawns each member via asyncio.create_task bounded by asyncio.Semaphore(FIRETEAM_MAX_CONCURRENT=3), and awaits them in a ~1s polling loop (asyncio.wait FIRST_COMPLETED) against a wave deadline (FIRETEAM_TIMEOUT_SEC=7200). It keeps a live member_snapshots dict (each member's final_state updated in-place during astream) so on timeout/cancel it still recovers real iteration/token/finding counts. Results are shaped into FireteamMemberResult dicts with status in {success,partial,error,timeout,cancelled,needs_confirmation}, iterations_used, tokens_used, findings, target_info_delta, pending_confirmation. (3) fireteam_member_think_node.py is the member ReAct step: builds the member prompt, calls the LLM with a parse-retry loop, strips forbidden actions, escalates dangerous tools for operator confirmation, writes ChainStep/ChainFinding/ExploitSuccess rows to Neo4j inline with agent attribution, and runs a productivity honesty audit. (4) fireteam_collect_node.py is the fan-in: merges each member's target_info_delta, rolls member findings into parent chain_findings_memory with source_agent attribution, writes a structured wave_entry into chain_waves_memory, auto-completes TODOs referencing succeeded members (breaks the redeploy loop), and drains a sequential escalation queue into the existing single-tool operator-confirmation flow. (5) fireteam_confirmation_registry.py is a process-global registry keyed by (session,wave,member) of PendingMemberConfirmation(asyncio.Event) entries plus reference-counted per-wave pause accounting that credits back operator-confirmation wait time to the wave deadline.

**Key abstractions (reusable):**
- build_fireteam_member_graph(*, llm_getter, tool_executor, streaming_callbacks, session_manager_base, neo4j_creds, graph_view_cyphers) -> compiled per-member StateGraph (checkpointer=None)
- FireteamMemberState (TypedDict): current_iteration, max_iterations, _decision, _pending_confirmation, _current_step, _current_plan, task_complete, completion_reason, fallback_uses_this_run, iterations_since_new_finding, last_findings_count
- Router fns _route_from_start / _route_after_member_think / _route_after_member_await_confirmation (iteration cap = strict-greater current_iter > max_iter -> fireteam_complete)
- fireteam_deploy_node(state, config, *, member_graph, ...) fan-out orchestrator
- _run_one(spec, member_id) inside 'async with asyncio.Semaphore(max_concurrent)', spawned by asyncio.create_task, awaited via polling asyncio.wait(timeout=min(remaining,1.0), return_when=FIRST_COMPLETED)
- _validate_mutex_groups(plan_members) singleton-tool contention guard
- _build_member_state(parent_state, spec, member_id, fireteam_id) with _seed_plan/_seed_single_tool to skip first LLM round
- _result_from_final_state / _cancelled_result / _timeout_result / _timeout_result_from_snapshot / _error_result
- FireteamMemberResult / ChainFindingExtract result models: status, iterations_used, tokens_used, findings, target_info_delta, pending_confirmation, wall_clock_seconds, execution_trace_summary
- member_snapshots dict (in-place final_state.update during astream) for partial-result recovery on cancel/timeout
- fireteam_collect_node fan-in: _merge_target_info (dedup-extend lists, dict-merge, scalar-if-empty), _render_summary, _auto_complete_fireteam_todos, chain_waves_memory wave_entry, _pending_escalations sequential drain

**What it does.** Seven small, layered defense modules wrapping an LLM-driven pentest agent. ## LLM conversation context management — a typed, reversible AST over reasoning/tool-call message chains (chain_ast.md) plus a multi-phase, invariant-preserving summarization/compaction engine built on it (chain_summary.md)

- **Repo:** vxcontrol/pentagi (backend/docs)  |  **Priority:** high
- **Files read:** https://raw.githubusercontent.com/vxcontrol/pentagi/main/backend/docs/chain_ast.md, https://raw.githubusercontent.com/vxcontrol/pentagi/main/backend/docs/chain_summary.md

**What it does.** Two coupled modules in pentagi's `pkg/cast`. (1) Chain-AST parses a raw provider message chain (`[]*llms.MessageContent`) into a typed, hierarchical tree — ChainAST -> ChainSection[] -> {Header, BodyPair[]} — where a Header is an optional System + optional Human message that opens a turn, and each BodyPair is one AI message plus its tool-response messages, typed by a BodyPairType enum (Completion / RequestResponse / Summarization). It round-trips losslessly: `NewChainAST(chain, force)` parses; `ast.Messages()` flattens back to a wire chain in exact order. It carries byte-size accounting at every level (sizeBytes / Size()), validates strict invariants (first msg System|Human, no consecutive humans, every tool call has a matching response by ID, no mid-chain system msg), offers a `force=true` repair mode (merge consecutive humans, inject placeholder tool responses), and handles provider-specific reasoning signatures (Gemini thought_signature, Anthropic cryptographic extended-thinking, Kimi/Moonshot reasoning-before-toolcall ordering). (2) Chain-Summary is a context-window compaction engine over that AST: a Summarizer with a SummarizerConfig runs three sequential, idempotent, goroutine-parallel phases — section summarization, last-section rotation of oversized body pairs, and QA-pair window summarization — collapsing old turns into a first-class Summarization node while hard-preserving the last body pair of each section and the last KeepQASections sections (because they hold irreplaceable reasoning signatures). Provider-migration helpers NormalizeToolCallIDs (rewrite tool-call IDs to a target provider's pattern, keeping call/response pairing consistent) and ClearReasoning (strip signature/thinking metadata) let a live chain move between providers.

- Non-fatal repair mode (force=true): inserts FallbackResponseContent placeholders for missing tool responses and merges consecutive human messages so a malformed chain becomes valid instead of erroring.

**VIGIL gap.** VIGIL has an authoritative append-only Ed25519 hash-chain SPINE (the ground-truth event log) but NO typed, structured, replayable, compressible VIEW over it for LLM context management. Concretely VIGIL lacks: (a) a deterministic projection of an event/message range into a typed AST (sections / headers / body-pairs) with tool-call<->response pairing made first-class and validatable; (b) lossless round-trip (parse a chain to a tree and render it back byte-for-byte) — needed to feed a bounded, well-formed context to Claude every turn; (c) principled, idempotent context COMPACTION with hard preservation invariants and byte-budget triggers, so long multi-turn recon/exploit runs don't overflow context; (d) provider/reasoning-signature awareness — preserving Claude extended-thinking signatures across compaction so the API doesn't reject the chain; (e) malformed-chain repair (missing tool responses, consecutive humans). This is exactly VIGIL's 'mature agent fs/job tooling' and 'attack-chain memory' gap at the context layer.

**Integration (through the provable layer).** Reimplement Chain-AST as a PURE, deterministic typed projection over a contiguous span of signed spine records (each spine event already carries a kind: system/human/AI/tool-call/tool-response/reasoning). Because the derivation is pure it is RE-EXECUTABLE: anyone can re-derive a byte-identical AST from the same signed span, matching VIGIL's veracity rule (re-execution, not string trust); the AST is a VIEW, never a mutation of the append-only spine. Extend BodyPairType with a veracity tag so every node is FACT (oracle-confirmed), LEAD (unconfirmed LLM claim), or SUMMARY (lossy) — so leads/summaries never masquerade as facts inside the agent's own context. Implement Chain-Summary compaction as APPEND-ONLY: a summary becomes a NEW signed spine record of kind Summarization that cites the hash/Merkle range of records it covers (RFC-6962 witnessed) plus the WARDEN-gated handler output; originals are never deleted, so verification always walks back to signed source. Route the SummarizeHandler LLM call through the egress gate and treat it as an A1 read/transform tier action; keep the produced summary labelled non-authoritative. Preserve pentagi's 'never summarize the last body pair / last KeepQASections' invariant to protect Claude extended-thinking signatures. Effort: M for the typed-AST projection + validation + round-trip; +M for the summarizer/config/invariants wired through the gates (total M-L). Main risk: a naive port treats summarization as IN-PLACE replacement, silently rewriting agent history and breaking the provable chain — it must be append-only-summary-as-signed-event, with the compressed AST purely a rendering choice for context assembly; secondary risk is dropping Claude thinking signatures during compaction (chain rejected by the API).

## Temporal knowledge-graph agent memory (Graphiti over Neo4j) + full observability stack (OTel Collector to Jaeger/VictoriaMetrics/Loki/ClickHouse/Grafana, plus Langfuse for LLM traces) + provider-agnostic LangChainGo LLM abstraction (Claude/Gemini/OpenAI)

- **Repo:** vxcontrol/pentagi (backend/pkg/graphiti/client.go, backend/docs/observability.md, backend/docs/llms_how_to.md) plus its dependency vxcontrol/graphiti-go-client (client.go, types.go)  |  **Priority:** high
- **Files read:** https://raw.githubusercontent.com/vxcontrol/pentagi/main/backend/pkg/graphiti/client.go, https://raw.githubusercontent.com/vxcontrol/pentagi/main/backend/docs/observability.md, https://raw.githubusercontent.com/vxcontrol/pentagi/main/backend/docs/llms_how_to.md, https://raw.githubusercontent.com/vxcontrol/graphiti-go-client/main/client.go, https://raw.githubusercontent.com/vxcontrol/graphiti-go-client/main/types.go

**What it does.** Three cooperating modules. (1) graphiti/client.go is a thin, enable/disable-gated, health-checked, timeout-bounded Go wrapper over graphiti-go-client giving the agent a bi-temporal knowledge graph: it ingests agent turns as Episodes/Messages (POST /messages, /entity-node) and exposes seven SPECIALIZED retrieval queries (temporal-window, entity-relationships, diverse-results [MMR], episode-context, successful-tools, recent-context, entity-by-label) plus generic /search and /get-memory, all namespaced by group_id. The graph stores Nodes (entities: UUID, Name, Labels[], Summary, Attributes map), Edges (Facts between two node UUIDs with bi-temporal validity), Episodes (raw content) and Communities (clusters). (2) observability.md wires ONE OpenTelemetry pipeline for traces/metrics/logs/profiles that fans out through an OTel Collector to Jaeger (traces), VictoriaMetrics (metrics), Loki (logs) and ClickHouse, visualized in Grafana; a Logrus->OTel hook (Fire) auto-correlates every log line to the active span's trace/span IDs, and a SEPARATE Langfuse path captures LLM observations with a rich taxonomy (Generation/Agent/Tool/Chain/Retriever/Evaluator/Embedding/Guardrail). (3) llms_how_to.md documents driving Claude, Gemini and OpenAI(-compatible: OpenRouter/DeepSeek/Together/Groq) behind one llms.Model interface, normalizing tool-call IDs and reasoning blocks across providers and handling per-provider prompt-caching and temperature quirks.

**Novel ideas:**
- Bi-temporal edges (valid_at/invalid_at over the world-timeline vs created_at/expired_at over graph-lifetime): facts are INVALIDATED not deleted, so contradictions and stale intel are represented as history rather than mutation -- a near-perfect fit for a provable audit trail where a refuted lead must remain on record
- A dedicated 'successful-tools' retrieval query: the memory graph is not just recall, it is a built-in learning substrate for 'what tool/technique worked in this situation before' -- a non-circular signal a metacognition loop can consume
- The Observation{ID,TraceID,Time} object threaded through BOTH the knowledge-graph client AND the telemetry stack, so every graph mutation/query is bound to the distributed trace that produced it -- unifying memory writes and operational tracing under one identity
- Two-plane observability: ONE OTel pipeline for infra signals (traces/metrics/logs/profiles) fanned out by a Collector, and a SEPARATE Langfuse plane with an LLM-native observation taxonomy (Generation/Tool/Guardrail/Evaluator) -- treating LLM reasoning as a first-class, differently-shaped signal rather than forcing it into generic spans
- Guardrail and Evaluator as first-class observation types -- an off-the-shelf telemetry shape for exactly the gate-block and oracle-verdict events a provable engine emits
- group_id namespacing giving cheap per-engagement graph isolation and whole-namespace teardown (DELETE /group/{groupID}, /clear)
- MMR diverse-results search as a distinct endpoint to actively de-duplicate retrieval, plus explicit score arrays (EdgeScores/NodeScores/MMRScores/MentionCounts) returned for downstream ranking/critique
- ChainAST as a provider-portability layer: validate the message chain, normalize tool-call IDs between OpenAI/Anthropic/Gemini formats, and preserve/clear reasoning signatures so a conversation can migrate providers mid-flight without corruption

**VIGIL gap.** VIGIL has a signed, append-only LINEAR spine but no queryable, temporal, entity-relationship GRAPH memory -- exactly the named "attack-chain graph memory" and "KB-RAG" gaps. Graphiti supplies: (a) entities as first-class nodes (hosts, services, creds, endpoints) with typed Labels + free Attributes; (b) relationships as bi-temporal Facts (valid_at/invalid_at = when true about the target; created_at/expired_at = when it entered/left the graph) so a refuted lead is INVALIDATED, never deleted -- audit history preserved; (c) episodes (agent turns) and communities (clusters); (d) a "successful-tools" query that is a ready-made non-circular learning signal ("what worked before"); (e) MMR diverse-results to fight retrieval redundancy. VIGIL also lacks operational observability entirely (no OTel/Grafana/Langfuse) and lacks LLM-safety-guard telemetry -- Langfuse's Guardrail/Evaluator observation types are the missing operational surface for its WARDEN gates and oracle verdicts. The multi-provider abstraction is largely redundant with VIGIL's Claude-everywhere stance, but its ChainAST tool-call/reasoning normalization and Anthropic caching/thinking handling harden VIGIL's own Claude tool-calling.

**Integration (through the provable layer).** Fuse the KG as a PROJECTION of the signed spine, never a parallel source of truth (this is the whole game). Concretely: (1) Run Graphiti+Neo4j as an internal service behind the host egress gate, holding no secrets. (2) Write a one-way projector that subscribes to the spine and mirrors ONLY oracle-confirmed+signed FACT records into the graph as entities/edges; each Edge carries provenance = the spine record hash + Ed25519 signature ref + a confirmation-status label. Unconfirmed items enter as a DISTINCT "lead" edge class so the LLM cannot launder a hypothesis into a "known" fact. (3) Map bi-temporal edges to VIGIL semantics: when an oracle refutes a lead, set invalid_at (do not delete) -- the graph inherits the provable audit trail. (4) group_id = per-engagement namespace bound to the charter/target; enforce charter-scoped authority on every KG read/write. (5) The agent uses the graph READ-ONLY to plan; any action it suggests ("pivot to host X") STILL passes the conjunctive gate (authority AND tier AND m-of-n threshold) and egress gate -- the graph informs, never authorizes. (6) Adopt the cross-cutting Observation{ID,TraceID,Time} pattern: thread the spine record hash / OTel trace id through spine writes, KG writes, and traces so the transparency log, signed corpus, and Grafana/Jaeger view share one identity (offline-verifiable AND debuggable). (7) Emit a Langfuse-style Guardrail observation on every WARDEN gate block and an Evaluator observation on every oracle confirm/refute. Effort: KG-as-projection = M; observability wiring = S/M (standard OTel); multi-provider = optional/skip. Main risk: TRUST LAUNDERING / dual-source-of-truth -- a graph the LLM treats as ground truth reintroduces hallucination through the back door, the exact failure VIGIL's veracity firewall exists to prevent; mitigate by projection-only writes, per-edge provenance+confirmation-status, a separate lead class, and forbidding any gate from reading authority out of the graph. Secondary risk: Neo4j is a new stateful attack surface -- keep it internal, egress-gated, secret-free, rebuildable from the spine.
