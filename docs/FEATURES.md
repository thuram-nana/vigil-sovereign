# VIGIL — feature catalog (every feature, and how it works)

The exhaustive, code-grounded inventory of what VIGIL does and **how each piece works** — one entry
per feature, each citing the `file:line` that implements it and its **honest status** (live / opt-in /
gated / scaffold / stub / conditional). This is the "nothing left out" companion to
[`AS-BUILT.md`](AS-BUILT.md) (the merged-status map), [`PLAN.md`](PLAN.md) (the design), and the
per-subsystem developer pages under [`../knowledge/kb/`](../knowledge/kb/).

> The one rule every entry is written under: **a claim is a FACT only when a deterministic oracle
> fires over bytes a real target produced.** The LLM proposes; the oracle confirms; the signature
> attests; the gates constrain. Where a feature is opt-in, gated, scaffolded, stubbed, or conditional,
> this doc says so **inline** — an honest catalog is worth more than an impressive one.
> **When this doc and the code disagree, the code and its tests win — fix this doc.**

**Coverage: 260 features across 7 domains** (the **2026-07 hardening additions** are catalogued in §7 —
per-action approval, gated Strix shell, how-to-verify everywhere, the proof-carrying-finding standard +
standalone verifier, attack-path/chokepoint, signed benchmark, calibration, coverage-guided discovery, and
the `engage --learn` auto-loop; the **2026-08 Verifiable-Fact program** adds `vigil remediate --prove` in §1
and the 12-entry verifiable-remediation cluster in §4 — the four-state remediation proof, F0–F4 freshness, the
live re-drive adapter, the continuous witnessed attestation series, the OOB tier, the standalone VIGIL-free
verifier, the trust gradient, and the deferred differential-remediation spec). This catalog was produced by a per-domain code-reading
inventory pass, then an **adversarial honesty + completeness re-read** of every section against the
cited code: that pass applied **68 inline honesty qualifiers/corrections** (e.g. it caught a draft
claiming `vigil authorize-destruction` opens its file `O_EXCL` when the code actually uses
`O_CREAT|O_TRUNC` and overwrites) and added **58 features the summary docs had left out**
(e.g. `vigil engage-instruct`, the `service_reachability` oracle, device revocation, `/api/inbox`,
`vigil learn-drain`, the scoped remote/LAN gate).

## 1. CLI and orchestration

VIGIL exposes two command-line surfaces. The **`vigil`** super-CLI (`integration/vigil_integration/cli.py`) is the unified control plane: it handles a set of NATIVE verbs in-process on the offense side, and forwards SUBSYSTEM verbs to each subsystem's own console-script EXEC'd in its own venv so the two trust domains never co-load. The **`python3 -m framework.v2 <subcommand>`** surface (`engine/crucible/framework/v2/__main__.py`) is the raw CRUCIBLE arsenal reached via `vigil crucible …`.

Two dispatch facts anchor everything below:
- The `vigil` `main()` intercepts subsystem verbs BEFORE argparse and forwards them opaquely (`cli.py:1104-1106`); all other verbs go through `build_parser()` (`cli.py:787-1095`). Uncaught exceptions become a clean one-line `vigil: error: …` with exit 1 (`cli.py:1108-1112`).
- Subsystem routing is by a hardcoded verb→environment table (`dispatch.py:23-29`), so an offense verb can never resolve into the sovereign venv or vice-versa.

### vigil engage — the attestation-first OODA loop
Purpose: run the unified engagement loop against an owner-authorized target (`cli.py:87-126`, parser `cli.py:795-822`). Args: positional `url`; `--slug` (default `loopback`), `--objective`, `--scope` (comma-separated literal hosts / `*.wildcards`, NO CIDR; default `127.0.0.1`), `--base-dir` (default `.vigil-live`), `--session` (per-session knowledge-graph partition key — organization only, grants no authority, empty falls back to the slug, `cli.py:806-809`), `--connect` (comma-separated connected session ids whose graph partitions are UNIONed as origin-tagged, non-authoritative priors, `cli.py:810-813`), `--replay` (a JSON file of scripted decisions → `ReplayThinker`, keyless-live, `cli.py:91-94`), `--access-log`/`--auth-log`/`--conn-log` (log inputs to the detection mirror), `--max-iterations` (default 12), `--approve-offense` (the operator's standing approval — the human leg of the conjunctive gate).
Mechanism: builds `EngineConfig` (with `api_key=None` hardcoded at `cli.py:101` — the engine resolves any key from env, never from argv) and `build_engine()` from `.live.wiring`; `--scope` is signed into the CRUCIBLE authority and enforced end-to-end (`cli.py:98-106`). Output: prints attestation ref, iterations/decisions, tool-call counts (ran vs denied), oracle-confirmed FACTS with evidence refs, LEADS, detection-mirror facts/leads, checkpoints, and a `paused` line if set (`cli.py:109-126`). Gate/oracle/spine: routes every action through the real gate + approval and every claimed exploit through the real oracle; writes signed spine checkpoints.
Failure/honesty: a refused engagement prints `REFUSED (fail-closed)` and returns 2 (`cli.py:110-112`). **Keyless (no `ANTHROPIC_API_KEY`, no `--replay`): per the module docstring it still attests first, then completes proposing NOTHING — it never fabricates activity** (`cli.py:40-42`; the guarantee is enforced in `build_engine`, not this file).

### vigil engage-instruct — mid-run advisory steering
Purpose: enqueue a natural-language operator instruction for a LIVE engagement `slug` (`cli.py:70-84`, parser `cli.py:824-831`). Args: positional `slug` + `text`, `--base-dir`. Mechanism: `.live.instructions.enqueue`; the running `vigil engage` folds it into its next think as ADVISORY context. **It fires nothing — every action still passes the gate + approval and every exploit still needs the oracle, so it can neither run a tool nor relax scope** (docstring `cli.py:71-74`). Output: `queued operator instruction #<seq> for engagement '<slug>' (advisory…)`. Failure: a `ValueError` (e.g. unknown slug) prints `refused:` and returns 2 (`cli.py:78-80`).

### vigil ledger who|when — usage-attestation replay
Purpose: replay the always-on usage-attestation ledger, non-repudiably (`cli.py:327-348`, parser `cli.py:833-837`). Args: positional `which` ∈ {who, when}; `--path` (default `.vigil-live/usage-ledger.jsonl`), `--base-dir`. Mechanism: `_load_and_verify_ledger` reads the ledger and verifies signatures + hash-chain under the operator key resolver rooted at `<base-dir>/operator.key` (`cli.py:318-324`) BEFORE printing — **fail-closed: a failed chain prints `LEDGER VERIFICATION FAILED (fail-closed)` and returns 3** (`cli.py:330-331`). `who` prints per-record operator identity (os-login, git-name, hostname, key fingerprint, action→target, phase, `cli.py:333-341`); `when` prints seq/at/monotonic and whether each is `TPM-anchored` (grounded) vs `software-chain` (`cli.py:342-347`).

### vigil verify-ledger — ledger integrity check
Purpose: verify the usage-attestation ledger's signatures + hash-chain (`cli.py:351-356`, parser `cli.py:839-842`). Args: `--path`, `--base-dir`. Output: `ledger: <n> records — VERIFIED/FAILED: <reason>`; returns 0 on ok else 3 (fail-closed).

### vigil verify — per-segment offense-spine verification
Purpose (S5b): the boundary-safe verification VIEW over the offense spine (`cli.py:359-392`, parser `cli.py:844-853`). Args: `--base-dir`, `--slug` (verify only `{slug}.spine`, default every `*.spine`), `--owner-pubkey` (pinned owner PUBLIC key, base64 — the delegation trust anchor), `--delegation` (a JSON file holding an owner-signed offense-spine `DelegationCert`), `--scope` (the scope the delegation must cover, default `*`). Mechanism: reads only PUBLIC keys + inert bytes; establishes the OWNER TIE by consuming an owner-signed offense-spine delegation (`OFFENSE_SPINE_ROLE` — this verb is that role's first live consumer, docstring `cli.py:360-364`); loads the `DelegationCert` via `vigil_core.delegation` then calls `.live.spine_verify.verify_offense_home`. Output: per-segment `[OK|FAIL|--|??]` status with owner-rooted vs not-owner-rooted tie. An unreadable/invalid cert refuses (returns 2, `cli.py:374-376`); **exit 3 iff any PRESENT segment FAILS integrity — absent (`--`) / unverifiable (`??`) segments are NOT failures** (`cli.py:387-392`). The sovereign spine is verified separately (`vigil sigil verify`) because one process cannot co-load both trust domains.

### vigil provision — mint a CRUCIBLE authority
Purpose: mint + sign a CRUCIBLE authority for a loopback slug (`cli.py:54-67`, parser `cli.py:855-863`). Args: `--slug` (default `loopback`), `--scope` (comma-separated literal hosts, no CIDR), `--environment` (default `twin`), `--hours` (default 8.0), `--max-actions` (default 1000), `--base-dir`. Mechanism: `.live.wiring.provision_authority` persists a STABLE governance key under `--base-dir`, sealed under its `Vault(<base-dir>/vault)` (`cli.py:58-62`), so a later `vigil engage --base-dir <same>` reuses the same anchor-1 signer and one owner delegation covers it (S7). Output: authority path + public key fingerprint.

### vigil identity — export offense stable identity (public keys)
Purpose (S7b): export the offense side's STABLE identity PUBLIC keys (spine + governance) as inert JSON for an owner-signed delegation (`cli.py:395-429`, parser `cli.py:865-868`). Args: `--base-dir`. Mechanism: loads-or-provisions the stable spine + governance keypairs (unsealing via `Vault`), writes `offense-identity.json` with `spine.key_id = SPINE_KEY_ID` and `governance.key_id = DEFAULT_KEY_ID` and their base64 public keys (`cli.py:409-421`). **Writes ONLY public keys — never a private key crosses.** Output tells the operator the next step is the sovereign `sigil delegate-offense …`, and warns to transport the file over an AUTHENTICATED channel (a swapped file would get an attacker's key owner-blessed, `cli.py:425-428`).

### vigil patch — gated auto-patch ladder (LAP-3b)
Purpose: run the gated auto-patch ladder over a PROVENANCE-GROUNDED confirmed finding (`cli.py:129-238`, parser `cli.py:870-921`). Finding source is EXACTLY ONE of `--finding-envelope` (a signed inert envelope: m-of-n governance signature verified with `vigil_core` under an owner-signed delegation; needs `--owner-pubkey`, `--delegation`, `--scope`) OR `--from-spine <slug>` (rebuild a confirmed fact from `{slug}.spine` after a fail-closed integrity audit; `--finding-ref` disambiguates when >1 fact). **A raw-JSON finding is never accepted** — passing both or neither source returns 2 (`cli.py:151-155`); a `TrustedFindingError` refuses fail-closed and returns 2 (`cli.py:167-169`). Other args: `--base-dir`, `--target-repo` (local path or git URL — operator deployment choice, NOT part of the signed finding, required or returns 2, `cli.py:185-187`), `--target-branch`, `--repo-base-dir` (disposable clone dir, default `.vigil-live/patch`), `--model` (Claude coder model; overrides Settings; API key from `ANTHROPIC_API_KEY` env, never argv, `cli.py:897-900`).
Legs (each an explicit opt-in; all off ⇒ non-destructive propose-only dry run): `--apply-edits` (apply the fix into the DISPOSABLE clone + sandbox-build; source never touched), `--approve` (standing approval for the reversible local legs), **`--open-pr` (OFF by default)** which requires `--signed-authorization`, `--authority-trust-root`, `--mandatory-signer` (≥1, must include owner), `--ledger` (the durable single-use nonce ledger dir), and a `GITHUB_TOKEN` in the environment. `--pr-base` sets the PR base branch. Mechanism: `--open-pr` auto-discovers the provisioned quorum under `--base-dir` (explicit flags override), loads the `DestructionAuthority` + signed authorization, and builds a `file_backed_quorum` whose single-use is durable + ATOMIC via the file-backed nonce ledger — one authorization → one PR (comment `cli.py:189-190`, wiring `cli.py:191-218`); then `autopatch_live` runs the ladder with `client=None` (coder built from env). Output: status, applied paths, opened_pr/pr_ref, remediated, reason. **Honest exit: non-zero (1) only on an outright refusal (status starts `refused`, i.e. not-confirmed / gate deny); a propose-only or applied-in-clone or opened-PR run is success, and "no proposal" (e.g. no API key) is reported, not crashed** (`cli.py:236-238`).

### vigil remediate --prove — four-state verifiable remediation proof (Verifiable-Fact program)
Purpose: prove a *remediation* by re-execution — re-drive the ORIGINAL retained exploit live against the (patched) target, re-fire the ORIGINAL oracle over the fresh wire bytes, and emit ONE signed, cross-bound certificate in one of four states: **REMEDIATED** (earned by oracle **silence** across the required trials, all controls satisfied) · **STILL_VULNERABLE** (the oracle fired over fresh evidence) · **INCONCLUSIVE** (testing happened, the negative claim not earned) · **REFUSED** (testing must not begin — out of scope / expired capability / non-certifiable family). `_cmd_remediate` (`cli.py`), driver `remediation/prove_driver.py`. Loads a PROVENANCE-GROUNDED finding (signed spine/envelope, never raw JSON) + the retained positive-control channel from `proofs/reverifiable.json`, reconstructs the exploit request (fail-closed — refuses if the request side was not retained), re-drives via `LiveHttpAdapter` through the gated `HttpExecutor`, prints the four states + writes the signed cert + inline-re-verifies (a REMEDIATED that doesn't re-verify → non-zero). **Downgrade-resistant: `--prove` only; NO `--skip-identity` / `--no-control` / `--allow-stale`.** Silence is only a fix when *controlled*: a positive-control twin must still FIRE (harness alive), the target must have ANSWERED (liveness), across a per-oracle-family repeat policy; a **fail-closed certifiable-family allowlist** REFUSES timing/race/credential-stuffing/prompt-injection/unknown classes. Freshness recorded F0–F4: **STILL_VULNERABLE reaches genuine F2** (the fresh nonce reflected in the sink's matched datastore-error line — as attributable as the oracle's own firing, NOT byte-unforgeable); **REMEDIATED caps at F1** (a fixed sink's traversal is unprovable — an F2-demanding verifier gets INCONCLUSIVE, never a false F2). Identity sampled 4× across the run (owner-attested policy + `WielderProof` proof-of-possession); an immutable `EffectiveAuthorization` + atomic budget bound the run. See [`../knowledge/kb/verifiable-fact.md`](../knowledge/kb/verifiable-fact.md) + [`proof-carrying-finding/TRUST-GRADIENT.md`](proof-carrying-finding/TRUST-GRADIENT.md).

### vigil provision-destruction — mint the m-of-n quorum
Purpose: mint the destruction quorum keys for `vigil patch --open-pr` (`cli.py:241-275`, parser `cli.py:923-934`). Args: `--base-dir`, `--threshold` (m, default 1 = solo owner), `--signers` (additional co-signer keys beyond owner, default 0), `--owner-id` (mandatory owner key id, default `owner`). Mechanism: `generate_authority` + `write_trust_root` writes the PUBLIC trust root under `--base-dir` and **prints each signer's PRIVATE key ONCE (explicitly NOT stored by the command)** (`cli.py:259-265`); a bad threshold/signer count raises `ValueError` → returns 2 (`cli.py:248-250`). **Off-by-default: nothing is armed until you also authorize AND pass `--open-pr`.** With threshold=1 it warns that whoever holds the owner key can authorize a PR (`cli.py:271-274`).

### vigil authorize-destruction — sign one destructive action
Purpose: sign ONE destructive action (from a `vigil patch` dry run) → the single-use, window-bounded signed authorization (`cli.py:278-315`, parser `cli.py:936-950`). Args (required): `--action-id` (the `pr-<remediation_id>` printed by the dry run), `--slug`, `--target` (must match). Others: `--base-dir`, `--out`, `--owner-id` (default `owner`), `--window-s` (default 600.0; total window must stay ≤900s dead-man's-switch), `--worker-key` (repeatable co-signer as `key_id=/path/to/keyfile`, read from FILE never argv). **The owner key is read from `VIGIL_DESTRUCTION_OWNER_KEY` env/Settings, never argv** — absent ⇒ returns 2 (`cli.py:286-290`); a bad worker-key spec or `sign_action` `ValueError` ⇒ returns 2 (`cli.py:294-304`). Mechanism: `sign_action` with a `fresh_nonce`; the output file is written **owner-only 0600 via `os.open(..., O_WRONLY|O_CREAT|O_TRUNC, 0o600)` — this OVERWRITES any prior file at the path (it is NOT `O_EXCL`; single-use is enforced downstream by the nonce ledger the PR leg checks, not by this open)** (`cli.py:305-309`). Output: signers, window (`single-use; within the 900s dead-man's-switch`), path.

### vigil proof-export — client-verifiable proof bundle (Proof Studio C1)
Purpose: assemble a CLIENT-VERIFIABLE proof bundle from a run's oracle-confirmed FACTs (`cli.py:462-493`, parser `cli.py:952-959`). Args: `--run-dir` (else `$VIGIL_PROOF_RUN_DIR`), `--out` (default `<run-dir>/proof-bundle`), `--slug` (default `engagement`), `--base-dir` (governance-key home; default = run dir). Mechanism: `.proof.bundle.export_bundle` (its docstring notes bundle.py lazy-imports framework; the governance private key is only ever an in-process argument, never argv — only the public trust root is written, `cli.py:466-468`). Output: bundle path, certificate count, and a trust-root fingerprint to PUBLISH OUT-OF-BAND (the client pins it via `--trust-root-fingerprint` so a bundle re-signed under another key is refused, `cli.py:489-492`). The bundle re-verifies OFFLINE with zero trust in VIGIL via `python -m framework.v2 evidence verify …` (exit 0 iff every certificate's signature, oracle reproduction, bound raw bytes, and the chain/head all hold). Missing run dir / export failure returns 1 (`cli.py:474-485`).

### vigil dossier — one-click tamper-evident run archive (R2/R3)
Purpose: compile EVERYTHING a run produced into ONE self-contained `.zip` (`cli.py:496-546`, parser `cli.py:961-975`). ### vigil terminal — governed local read/inspect command
Purpose: run a governed LOCAL read/inspect command through the same conjunctive gate + sealed spine signer the live engine uses (`cli.py:675-728`, parser `cli.py:1060-1075`). Args: positional `command` (nargs+); `--approve`, `--base-dir`, `--slug` (default `loopback`). Mechanism: `build_terminal_runtime` reuses the exact building blocks; `execute_terminal` parses + allowlist-validates the command (NO shell, argv list, LOCAL read/print binaries only), classifies `terminal.run` at WARDEN A2. **A2 → QUEUES under the A1 offense ceiling, never auto; without `--approve` the base gate QUEUES and `execute_terminal` denies at authorization — the command is prepared + gated but never run** (`cli.py:707-710`). `--approve` selects `rt.approval_gate` (the same `_approval_gate` wiring path) to upgrade the A2 queue to allow. A successful run writes a signed, redacted `ExecRecord` appended to the read-only terminal history (`cli.py:719-721`). **Fail-closed at every stage: an unbuildable gate/signer, no signer, or an off-allowlist command all yield a clean JSON refusal (`ran=false`), never a raise** (`cli.py:701-705`). Returns 0 iff the command ran, else 2.

### vigil sandbox — arbitrary command in a bwrap sandbox
Purpose: run an ARBITRARY command inside the network-isolated, workspace-confined bwrap sandbox (`cli.py:731-784`, parser `cli.py:1077-1093`). Per the docstring a **missing bwrap is a clean refusal (NO un-sandboxed fallback)** (enforced in `execute_sandbox`); fail-closed at every stage; a successful run writes a signed, redacted `ExecRecord` to `sandbox-history.jsonl` (`cli.py:774-777`). Returns 0 iff the command ran, else 2.

### vigil <subsystem> — subsystem passthrough (S1 control plane)
Five hardcoded passthrough verbs forward to a subsystem's own console-script EXEC'd in its FIXED environment (`dispatch.py:23-31`, intercepted at `cli.py:1104-1106`): `sigil` → `.venv-sovereign/bin/sigil` (the sovereign personal core, holds the owner key), `crucible` → `.venv-offense/bin/crucible` (the raw CRUCIBLE arsenal — its own engage/scan/plan/…), `aegis` → `.venv-offense/bin/aegis` (the defensive dual: detect/gateway/demo), `strix` → `.venv-offense/bin/strix` (the agent body), `gateway` → `.venv-offense/bin/vigil-gateway` (the host egress gate). Mechanism: `dispatch.dispatch` resolves the absolute console-script path (root via `VIGIL_ROOT` / venv-parent / walk-up marker, `dispatch.py:38-55`) and `subprocess.run`s it, **stripping `PYTHONPATH`/`PYTHONHOME` from the child env so a parent-injected path can never inject the other trust domain's modules** (`dispatch.py:86`), inheriting stdio, passing `argv` as a LIST (no shell). Failure modes: an unknown verb passed to `resolve`/`dispatch` → 2 (`dispatch.py:72-74`); env not built (script missing) → 127 with a build hint (`dispatch.py:76-79`); un-executable script (half-built venv, `OSError`) → 127 (`dispatch.py:92-97`). ## `vigil up` / `vigil down` sidecar orchestration
Implemented in `integration/vigil_integration/uiproxy.py` — **PURE STDLIB, EXEC-ONLY**: it imports NEITHER framework/strix NOR sigil; the backends run as SEPARATE OS processes in their own venvs (spawned via `dispatch.resolve`) so one interpreter never co-loads the two trust domains (`uiproxy.py:13-17`).

### Never-public bind + authority
`run_up` refuses a public bind up-front via `bind_ok` (returns 2, `uiproxy.py:668-672`): loopback, IPv4 RFC1918/Tailscale-CGNAT (`100.64.0.0/10`), or IPv6 ULA (`fc00::/7`)/link-local (`fe80::/10`) only — never `0.0.0.0`/`::`/globally-routable. IPv6 uses a POSITIVE allowlist because Python mislabels Teredo/6to4 as private (`uiproxy.py:101-116`). `compute_authority` derives the browser authority/scheme/auto-open: `--domain` → https, no auto-open; loopback → http + auto-open (`uiproxy.py:126-141`). **A `--domain` deployment with `CRUCIBLE_API_KEY` unset and no `--insecure-no-api-key` is REFUSED (returns 2)** so the gated offense api is never internet-exposed unauthenticated (`uiproxy.py:680-685`).

### Processes spawned (into `procs`)
1. **sovereign-cockpit** — `sigil serve --host 127.0.0.1 --port 8733 --allow-host <authority> --allow-origin <origin>`, spawned via `_spawn_capture` which tees stdout to a 0600 log AND scans it; `_await_token` reads until the `?token=` appears (20s timeout). No token ⇒ abort + cleanup, return 1 (`uiproxy.py:724-734`).
2. **offense-console** — `crucible console --port 8787 --allow-host … --allow-origin …` with `VIGIL_LIVE_DIR` pointed at the resolved base and `VIGIL_BIN` set to the sibling `vigil` path (so its graph-backed engage doesn't silently fall back when `vigil` isn't on PATH, `uiproxy.py:574-583,741-754`).
3. **offense-api** — `crucible api --port 8799 --allow-host … --allow-origin …` (the gated `/api/v1` action plane, `uiproxy.py:743-756`).
   Both offense children receive the LLM key/model env resolved from the sovereign venv via a subprocess (`_resolve_offense_llm_env` → `sigil settings export-runtime-env --include-secrets`), consumer-allowlisted by `_OFFENSE_ENV_ALLOWLIST` (`uiproxy.py:440-467,530-557`); **`VIGIL_DESTRUCTION_OWNER_KEY` is the ONE hard exclusion — a keyless offense process must never receive the auto-patch signing key** (it is absent from the allowlist, comment `uiproxy.py:436-438`). BASE64 file-content creds (GCP JSON / kubeconfig) are materialised to fixed-name 0600 files (symlink/hardlink-safe via `os.unlink`-then-`O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW` + `st_nlink==1`) and handed to the child only as a PATH (`uiproxy.py:472-527`); the raw content var is always dropped from the child env even on failure.

8. **sovereign-voice** (opt-in `--with-voice`) — `sigil voice --mic` (the S2 voice-nav producer; **needs a mic**, `uiproxy.py:810-812`).
9. `--with-gesture` (opt-in) — NOT a persistent process: a one-shot `sigil gesture-nav on` flips the S3 nav-mode latch so an owner-armed PHONE gesture session navigates. **Local camera gesture is NOT functional — gesture input is the phone companion** (`uiproxy.py:804-819`). Both S2/S3 are A1 signals that inject nothing into the OS.

### Serve dir + proxy + pids
`assemble_serve_dir` builds a **0700** runtime serve dir under `.vigil-live/ui/` from `packages/vigil-ui`: concatenates `tokens.css`+`components.css` → `style.css`, copies `ui.js`/`manual.js`/`app.js` (+ `manifest.json`, + the committed `system-map.json`), and writes `index.html` with the sovereign session TOKEN + federated mount bases substituted, chmod 0600 (token-bearing, `uiproxy.py:153-186`). `make_proxy_server` binds the ONLY human-facing listener (threaded for concurrent SSE, `uiproxy.py:209-223,391-400`). `route()` maps `/sovereign/*` → 8733, `/offense/api/v1/*` → 8799 (the gated api), everything else under `/offense/*` → 8787 (the console read+SSE plane); the api is disambiguated by its `/api/v1` sub-prefix (`uiproxy.py:192-206`, rationale `uiproxy.py:24-32`). The proxy faithfully forwards headers minus hop-by-hop (`uiproxy.py:83-87,339-349`), bounds request bodies at 16 MiB (413 on excess, `uiproxy.py:60,315-318`), streams responses by closing the connection (SSE-safe, forwarding each event as it arrives, `uiproxy.py:351-374`), serves the static bundle with a strict same-origin CSP + `X-Content-Type-Options: nosniff` + `Referrer-Policy: no-referrer` (`uiproxy.py:80-81,298-304`), never traverses out of the serve dir for static files (`uiproxy.py:280-290`), drains + closes each static response to defeat request smuggling (`uiproxy.py:294-297`), and redacts `?token=` from access logs (`uiproxy.py:231-237`).

`_write_pids` records the orchestrator PID + every child PID to `.vigil-live/ui/pids` (`uiproxy.py:632-635,837-838`); SIGINT/SIGTERM set a stop event + `httpd.shutdown`, and the `finally` runs `_cleanup` (SIGTERM each live child, `p.wait(timeout=5)`, then kill) and unlinks the pids file (`uiproxy.py:856-878`). **`vigil down`** (`run_down`) reads that pids file, sorts children-first/orchestrator-last, and `_terminate`s each (SIGTERM → 5s grace → SIGKILL); a missing/empty pids file is a clean no-op (`uiproxy.py:883-909`).

## 3. The live execution layer and the gate of record

The live execution layer is the choke point where an LLM-proposed tool call becomes real bytes on the wire — or is denied. Its one job for a network tool: **no subprocess spawns unless the target clears the egress floor AND the full conjunctive gate allows, both fail-closed, before a single byte is written.** The two non-network tiers (local terminal, bwrap sandbox) reuse the same gate + signed-record machinery but preserve the egress floor by construction (allowlist) or by kernel isolation instead of an IP-pin. Every path degrades to a DENY on malformed input and never raises. All governance is composed as injected thunks over one pure gate-of-record so it is testable without a live kernel.

Sources: `integration/vigil_integration/live/executor.py`, `.../wiring.py`, `.../engine.py`, `.../sandbox_exec.py`, `.../approval_token.py`, `.../nonce_ledger.py`, `.../destruction_provision.py`, `integration/vigil_integration/conjunctive_gate.py`, `.../warden_gate.py`, `.../destruction_gate.py`, `integration/vigil_integration/tools/governance.py`, `.../agent/targets.py`, `packages/core/vigil_core/vigil_core/gate.py`.

### The governed network executor: `execute()` (executor.py:614-713)

`execute(tool_name, tool_args, phase, *, gate, view, destructive_view, run, signer, seq, now, timeout, output_cap, scope, allowed_ips)` runs a strict deny-by-default pipeline. The public entry (`executor.py:638-644`) wraps `_execute` in a bare `except` that returns `_deny(name, "internal error … (fail-closed)")` — **an internal error is always a DENY, never a raise.** Ordered stages (`_execute`, executor.py:647-713):

- **(0) Name + recordability.** Empty/non-str tool name → DENY (executor.py:649-651). **No signer wired → DENY *before any spawn*** — an unrecordable call is unprovable, so it is refused (executor.py:655-656). Unknown tool (no builder in `_BUILDERS`) → DENY (executor.py:658-660).
- **(1) Egress guard.** `_resolve_scoped_target(extract_target(tool_args), scope=scope, allowed_ips=allowed_ips)` resolves and pins the target *before* authorization and *before* any subprocess (executor.py:665-668). `pinned is None` → DENY with the precise reason.
- **(2) Authorization.** `authorize_tool_call(tool_name, tool_args, phase, gate=…, view=…, destructive_view=…, resolved_target=_scope_target(pinned), now=now)` — proceeds ONLY on `verdict.allowed` (executor.py:675-683). AUDIT-G4: the gate scopes on the executor-**validated hostname** (`_scope_target` returns `raw_host`+port, executor.py:377-383), never the LLM's proposed string or the resolved IP.
- **(3) Argv build + run.** A pinned host that parses as a flag (`startswith("-")`) → DENY (executor.py:686-689). The per-tool builder returns `None` on any unsafe/smuggled/missing option → DENY (executor.py:690-694). The argv LIST runs via injected `run` (default `subprocess_runner`); a runner exception is captured as a failed `RunOutcome`, never a crash (executor.py:697-701).
- **(4) Signed, redacted record.** `_build_record` writes a signed `ExecRecord`; RAW stdout/stderr is returned to the caller for the oracle but **never persisted** (executor.py:704-713).

`ExecResult.ran`/`.allowed` (a property returning `self.ran`) is True only when every gate passed and the runner was invoked (executor.py:233-259).

### The egress guard: `_resolve_scoped_target` (executor.py:287-363)

Parses the target with `urlsplit` (fail-closed on malformed port / unparseable / no host, executor.py:306-319), resolves with `socket.getaddrinfo` (executor.py:322-331; any resolve failure → DENY), then two modes:

- **`scope is None` — loopback-only (the fail-closed DEFAULT, every direct caller/test).** Refuses unless *every* resolved address is IPv4 loopback `127.0.0.0/8`. IPv6 `::1` is explicitly refused (executor.py:342-344). A non-loopback IP is refused, with `vigil_gateway.denylist.is_egress_denied(ip)` consulted only for the *reason* on the deny branch — it is an independent second refusal, never the allow decision (a public IP it would "allow" is still refused because it is non-loopback) (executor.py:345-347). Pin = deterministic `sorted(ips, key=ip_address)[0]` (executor.py:348) — every ip here is already IPv4 loopback.
- **`scope` provided — signed-authority remote/LAN path (opt-in / production-wired via `wiring._offense_scope_source`).** `scope.matches(host)` must hold (else DENY, executor.py:352-353); every resolved IP must clear `is_egress_denied(ip, allowed, loopback_allowed_if_scoped=True)` (executor.py:355-358) — here `is_egress_denied` IS the allow decision; then it pins the **exact resolved IP** with plain `sorted(ips)[0]` (a deterministic multi-homed record without a v4/v6 comparison error) — resolve-once-pin-exact-IP as TOCTOU/DNS-rebind defence (executor.py:359-363). **The metadata/link-local/reserved egress floor is never liftable by any scope** — loopback is reachable only when the signed scope authorises it. *(Previously undocumented in AS-BUILT/README, which describe only the loopback pin.)*

The pinned components (`_Pinned`, executor.py:274-284) are the ONLY source the argv builders reconstruct from — a smuggled second host (`127.0.0.1@evil.com`, `127.0.0.1 evil.com`) can never survive into an argv.

### `subprocess_runner` — the default live runner (executor.py:149-176)

Spawns `argv` with `subprocess.run(shell=False, check=False, stdin=DEVNULL)`, capturing both streams under a wall-time `timeout` (default 120s, executor.py:78) and truncating each to `output_cap` (default 1,000,000 chars, executor.py:79). `stdin=DEVNULL` prevents an allowlisted stdin-reading command from blocking to the timeout (executor.py:162-167). `TimeoutExpired` → `RunOutcome(exit_code=None, timed_out=True)`; `OSError/ValueError` → captured `spawn failed:` outcome (executor.py:168-176). Argv is always a LIST; **no shell, no string interpolation anywhere.** An injected `run` return is normalised through `_coerce_outcome` (executor.py:179-188), so a fake/echo runner exercises the identical gate/oracle/spine path.

### The six network argv builders (`_BUILDERS`, executor.py:488-584)

Every builder reconstructs the target from `_Pinned` only and returns `None` (→ DENY) on any smuggled host or missing/unsafe required option. URL builders use `_pinned_url` (executor.py:391-401), which rebuilds `scheme://<pinned-netloc><host-free path>?<host-free query>` so nothing can redirect the connect host.

- **`_build_nmap` (executor.py:488-498):** `["nmap","-Pn","-n", …, p.host]`. Ports from `_valid_ports` (regex `_PORT_SPEC_RE`, executor.py:416, each token 1..65535, executor.py:431-439) else the pinned port; `service_detection`/`sV is True` → `-sV`. The pinned `127.0.0.0/8` literal is appended last (never starts with `-`).
- **`_build_httpx` (executor.py:501-505):** `["httpx","-u",url,"-silent","-no-color","-disable-update-check","-json"]` over the pinned URL. Ignores all other `tool_args` for targeting.
- **`_build_nuclei` (executor.py:507-516):** `["nuclei","-target",url,"-jsonl",…]`; optional `-tags`/`-severity` only if they pass `_safe_csv` (`_CSV_TOKEN_RE`, executor.py:417/442-443).
- **`_build_ffuf` (executor.py:519-528):** requires a `wordlist` that passes `_local_file` — an existing LOCAL file, refusing any `://` or non-file (executor.py:458-467); a smuggled `http://evil/…` never satisfies `isfile`. Inserts a `FUZZ` marker into the path if absent. Missing wordlist → `None`.
- **`_build_sqlmap` (executor.py:531-545):** `["sqlmap","-u",url,"--batch","--disable-coloring"]`; optional `--level` (1..5) / `--risk` (1..3) via `_int_in`; optional `--data` POST body (sent to the pinned host; inline secrets scrubbed by `_redact_str` in the record).
- **`_build_hydra` (executor.py:548-574):** requires a `service`/`module` passing `_safe_token` (else `None`); `-s <port>` if pinned; a username via `_safe_login` (no whitespace/leading-`-`/scheme, executor.py:469-476) → `-l`, else a `_local_file` userlist → `-L`, else `None`; an inline `password` (non-`-`) → `-p` **with its argv index recorded in `secret_idx`** so the record masks it, else a `_local_file` passlist → `-P`, else `None`.

Record redaction (`_redact_argv`, executor.py:479-485) runs the F3 `_redact_arg_list` scrubber (one vocabulary: `--secret-flag value`, inline Bearer/kv/url-userinfo) then overlays tool-specific secret positions (hydra's `-p`) as `••••`.

### Signed, redacted `ExecRecord` (executor.py:196-231, 598-611)

`ExecRecord` is a pydantic append-only record: `seq`/`now` (deterministic coordinates), tool/phase/tier/destructive/requires_quorum, canonical loopback `target`, **REDACTED** argv, exit_code/timed_out/truncated, `stdout_sha256`/`stderr_sha256` over the **RAW** streams (the provable link to what the oracle re-examines, without storing plaintext), and REDACTED capped stdout/stderr. `signing_bytes()` is sorted-key tight-separator JSON with the signature excluded (executor.py:221-226). `_sign` (executor.py:105-116) is fail-closed: a missing/erroring signer or a non-str/empty return yields `""` (an *unsigned* record) — never a fabricated signature, never a crash. (The write path already refused up front if no signer was wired; this guards a signer that raises after the irreversible spawn.)

### `authorize_tool_call` — the phase manifest + tier + gate driver (governance.py:176-235)

Order (fail-closed, never raises): **(1)** coerce phase (`None` → DENY A3); **(2)** `is_tool_allowed_in_phase` against `view` (governance.py:94-104) — an unregistered/out-of-phase tool is DENIED *before the gate is consulted* (governance.py:210-213); **(3)** destructive classification — the operator manifest `destructive_view` is authoritative, `is_destructive_tool` raises the floor further (governance.py:205-207); **(4)** target selection — AUDIT-G4: when the authoritative caller supplies `resolved_target` it gates on THAT (an explicitly-blank resolved target → DENY, governance.py:217-221); else falls back to `extract_target(tool_args)` (the non-authoritative pre-check path); **(5)** `gate is None` → DENY; a gate exception → DENY (governance.py:224-230). `allowed` requires `verdict.allowed is True AND outcome == "allow"` (governance.py:232). `extract_target` (agent/targets.py:22-31) reads the first non-empty of `TARGET_KEYS = ("target","url","target_url","host","domain")` — one shared helper so triage/gate/executor never drift.

**`is_destructive_tool` (governance.py:68-80)** is the known-dangerous-name floor: the operator's declared flag wins (`declared` True → destructive), else the name is matched against the `_DESTRUCTIVE_TOOLS` frozenset (metasploit/hydra/sqlmap/nuclei/hashcat/mimikatz/netcat/… governance.py:39-58) OR the `_DESTRUCTIVE_PATTERNS` substring families (`_dos`, `reverse_shell`, `_brute`, `cobalt`, … governance.py:59-65). Raise-only — over-inclusion is the safe direction. **`redact_tool_args` (governance.py:150-163)** scrubs secrets from the args before they hit the spine, descending nested dicts/lists to a bounded depth (`_redact_value`, governance.py:129-147); a purely positional secret is a documented residual. **`authorized_tool_names` (governance.py:238-247)** is the pure phase-view menu the LLM is shown — being on it is necessary but not sufficient, every call re-clears the gate at execution.

### The CONJUNCTIVE gate of record: `conjunctive_decide` (vigil_core/gate.py:63-120)

The ONE pure composition both trust domains import (lives in neutral `vigil_core`, gate.py:1-22). Both halves are injected thunks; first-failure-wins; **ANY error in ANY conjunct → DENY, never caught-and-continued.** Order:

1. **CRUCIBLE domain authority first** (its killswitch step has absolute precedence). A raised refusal or any error → DENY (gate.py:75-78); `not allowed` → DENY (gate.py:79-80).
2. **WARDEN tool gate.** A classifier/gate error → DENY (gate.py:83-86).
3. **Threshold-destruction (destructive only).** No destruction gate wired → DENY; a gate error → DENY; **strict `authorized is True`** identity check — a truthy-but-not-`True` value must NOT open an irreversible action (gate.py:91-109).
4. Final verdict: `war.outcome == "auto"` → ALLOW; `"queue"` → QUEUE (in-envelope, needs owner approval); **any other/unrecognised outcome → DENY** — only an explicit `"auto"` may open the gate (gate.py:111-120).

`GateVerdict` carries `allowed/outcome/reason/crucible_allowed/warden` (gate.py:38-45).

### `build_offense_gate` — wiring the real conjuncts (conjunctive_gate.py:71-174)

Returns `gate(tool_name, target_url, destructive=False, *, destruction_action=None, destruction_signed=None)`. **`trust_root is None` is refused at build time** (conjunctive_gate.py:106-111) — a None trust root would load the CRUCIBLE authority unsigned (the seam map's biggest fail-open). The CRUCIBLE thunk lazily imports `framework.v2.authority.gate.authorize_action` + `load_authority_for_gate(slug, trust_root)` (verified load) and builds an `ActionRequest(action_kind="offense", destructive=…)` (conjunctive_gate.py:121-132). WARDEN thunk = `decide_tool(...)`. The `now` value is adapted per-leg: `_as_datetime` for CRUCIBLE, `_as_epoch` for destruction (conjunctive_gate.py:46-68) — the confirmed gate bug was one `now` typed for only one leg. The destruction thunk is wired **only** when `destructive AND destruction_authority AND destruction_action AND destruction_signed AND is_consumed` are all present, and **cross-binds** the quorum's `target`/`engagement_slug` to the CRUCIBLE half's — a divergence yields an unauthorized `DestructionOutcome` (conjunctive_gate.py:139-165). A destructive call missing any piece reaches `conjunctive_decide` with no gate → DENY.

**`_build_gate` (wiring.py:512-533)** is the offense-side factory that also wires the operator **KillSwitch** into the gate: `KillSwitch(prov.slug)` is constructed and passed to `build_offense_gate` (previously omitted, so a tripped killswitch would not have halted this gate). It is fail-**soft** — a KillSwitch build failure keeps the gate — which is safe because `KillSwitch(slug)` is I/O-free and can only throw if `framework` itself is unimportable, in which case the CRUCIBLE leg's own lazy `authorize_action` import also fails at call time and `conjunctive_decide` DENIES anyway. Any failure building the gate itself leaves it `None` ⇒ every tool call DENIED. *(The kill-switch wiring was previously undocumented.)*

### WARDEN tool-tier gate: `decide_tool` (warden_gate.py:80-112)

Tiers `A0..A3` as kernel string labels + ordinals. Pure, injected classifier, fail-closed: empty name → DENY A3; denylisted → DENY A3; classifier garbage → treated as A3 (warden_gate.py:95-104). `tier = max(classify(name), floor)` (raise-only, `_tier_max`, warden_gate.py:76-77). `DEFAULT_FLOOR="A2"`, `DEFAULT_CEILING="A1"`, `AUTO_BAR="A1"` (warden_gate.py:52-54). AUTO iff `tier <= A1 AND tier <= ceiling` (an unknown ceiling defaults to ordinal 0 = strictest), else **QUEUE** (warden_gate.py:107-112). **At the DEFAULT posture (A2 floor + A1 ceiling) every offense tool queues — offense never auto-runs.** This is a *posture default*, not an invariant: the module docstring and `EngineConfig.offense_ceiling` (wiring.py:210-215) explicitly allow an operator to lower the floor to A1 on a TWIN/STAGING target so recon auto-runs while destructive/exec stays A3→queue.

`kernel_classifier` (sigil-kernel subprocess, warden_gate.py:115-157) is OPTIONAL and *not wired live* (the live gate uses the pure in-process `default_classify`); an unresolved binary fail-closes to A3 and never bare-name-execs an attacker-planted PATH binary (warden_gate.py:131,137-138). The Strix `WardenGateHooks` soft-wire (`attach_from_env`) is **ON BY DEFAULT (opt-OUT via `VIGIL_WARDEN_STRIX_GATE`)**; a non-AUTO (QUEUE) classification is **APPROVE-THEN-RUN (wired, T5/#178)** — routed to the per-action, single-use, owner-signed approval broker (publish pending → wait for a matching signed token, offloaded off the asyncio event loop → spend once → the ONE call runs), else it raises; with NO authority provisioned a QUEUE hard-blocks (fail-safe) (warden_gate.py:204-239). `compose_run_hooks` (warden_gate.py:214-258) fans N openai-agents `RunHooks` into one so Strix's usage accounting AND the WARDEN `on_tool_start` gate run off a single hooks object; a `WardenDenied` raised by a member propagates (that is how a denied classification blocks the tool call).

### Tool tiering: `DEFAULT_TOOL_VIEW` / `DEFAULT_DESTRUCTIVE_VIEW` / `default_classify` (wiring.py:52-93)

- `DEFAULT_TOOL_VIEW` (wiring.py:53-71): the tool→phase manifest (unlisted-in-phase → DENY). nmap/httpx/nuclei/ffuf/curl in informational+exploitation; sqlmap/hydra in exploitation+post_exploitation; `terminal.run` and `sandbox.exec` in all three.
- `DEFAULT_DESTRUCTIVE_VIEW` (wiring.py:73): `{"sqlmap": True, "hydra": True, "metasploit": True}` — authoritative for the m-of-n leg.
- `default_classify` (wiring.py:79-93): derives DANGER from the ONE shared `vigil_core.warden_tiers.has_danger_token` (byte-faithful Rust-kernel port). A curated danger-free recon name (`_RECON`, wiring.py:76) → A1 (auto-eligible, the floor still decides); a name with an A3 danger token → A3 (matches the kernel); else A2. `sandbox.exec` carries an A3 token → A3; `terminal.run` has none → A2 (queues under the A1 ceiling).

### The signed-authority sources: `provision_authority` + `_offense_scope_source` (wiring.py:120-168, 233-251)

**`provision_authority` (wiring.py:120-168)** creates and **signs** the CRUCIBLE authority the gate loads-verified: it builds a single-signer `TrustRoot`, an authority-from-scope doc, signs it, and persists it. Scope hosts are **LITERAL** (`["127.0.0.1"]`, no CIDR). The governance key is stable + vault-sealed when a `base_dir` is supplied, else a legacy per-run ephemeral key. **`_offense_scope_source` (wiring.py:233-251)** is the `ScopeSource` the executor's scoped egress branch consults, re-loaded per call from the same signed authority (a mid-engagement re-sign is honoured). Fail-closed: any load/verify failure makes `hosts()` return `[]` → empty scope → the executor **denies EVERY target, including loopback** (strictly closed). In `build_engine` (wiring.py:302-307) `offense_scope` is only set when a trust root is present; a lazy import failure leaves it `None` → the executor falls back to loopback-only (also fail-closed, less strict).

### M2 per-action approval token (approval_token.py, wiring.py:556-612)

The high-assurance opt-in alternative to the standing boolean. `ApprovalToken` binds the exact `(tool_name, target, action_digest)` (approval_token.py:102-136); `action_digest` is `sha256:` over canonical `{tool_name,target,args}` (approval_token.py:64-70), so a token for `sqlmap … --dump` cannot authorize `--os-shell`. `verify_token` (approval_token.py:208-272) runs **seven** fail-closed checks in order: schema; action binding (`token.matches`); validity window (`not_before<=now<=not_after`, NaN → deny); dead-man's-switch (positive window, `<= max_token_lifetime` default 900s, approval_token.py:139-147); **owner key pin** — `token.key_id` must equal the immutable `ApprovalAuthority.owner_key_id` (approval_token.py:248-252; the I4 free-`owner_key_id` BLOCK class); single-use advisory `is_consumed`; Ed25519 signature over `token_signing_bytes` (domain-tagged `vigil-peraction-approval-v1`, approval_token.py:55/162-163) against the PINNED public key. `_well_formed` uses **exact-type checks** (`type(x) is C`) so a behaviour-overriding subclass can't decouple binding from the signed bytes (approval_token.py:191-205). `consume_token` (approval_token.py:275-304) does the ATOMIC check-and-burn via `NonceLedger.try_consume` (`O_CREAT|O_EXCL` per-nonce marker, filename = `sha256(nonce)`, as the serialization point, nonce_ledger.py:53-73) — the burn happens ONLY after signature+binding+window pass, so an invalid token can never grief-burn a victim's nonce; losing the race → DENY (replay). `require_approval` (approval_token.py:307-316) is the raise-entry (`ApprovalRefused`), the M2 sibling of `require_destruction_authorization`.

`build_approval_gate` (wiring.py:556-612) is the M2 gate wrapper: it upgrades a WARDEN `"queue"` to `"allow"` ONLY when `token_source()` returns a `(token, action)` whose named tool+target equal the gate call AND `consume_token` authorizes it. **A CRUCIBLE `"deny"` is returned untouched — a token can never widen scope, lift the kill-switch, or authorize a denied action.** Any token-source/verify error leaves the action queued (the executor then denies). *(build_approval_gate has 0 hits in AS-BUILT.md — previously undocumented.)* When `config.approval_authority` is None the engine wires `_approval_gate` (wiring.py:536-553) — the lower-assurance standing-boolean upgrade — whose activation is driven by the engine's `approval` seam returning `config.owner_approves_offense` (default **False**, wiring.py:216-221, 371-374).

### m-of-n threshold destruction: `destruction_gate` (destruction_gate.py)

The highest-consequence gate: an autonomous (prompt-injectable) worker must not perform an irreversible action alone. `authorize_destruction` (destruction_gate.py:216-279) is fail-closed, first-failure-wins, over: **(0)** the class must be a gated class (destructive/high-blast, else refused so a mislabel can't dodge the gate, destruction_gate.py:238-239); **(1) action binding** — `auth.matches(action)` on `(action_id, engagement_slug, target, blast_class)`; **(2) validity window** (NaN → deny); **(3) dead-man's-switch** — window positive, `<= max_authorization_lifetime` default 900s; **(4) single-use** — a nonce checked against the required `is_consumed` (re-derived from the spine, survives restart); **(5) m-of-n threshold** via `vigil_core.verify_threshold` (low-order keys + duplicate key_ids barred at the crypto core) plus **mandatory owner** — every `authority.mandatory_signer_ids` (immutable deployment config, validated a non-empty subset of the trust root at construction, destruction_gate.py:89-96) must be among the valid signers (destruction_gate.py:273-277). `_well_formed` (destruction_gate.py:191-213) uses exact-type checks. `require_destruction_authorization` (destruction_gate.py:282-295) raises `DestructionRefused` and is called by the privileged executor holding the deployment authority, never by the agent. FROST aggregation and the OpenTimestamps anchor are **deferred refinements** that do not change the m-of-n property (destruction_gate.py:18-21).

### `destruction_provision` — minting/signing the quorum (destruction_provision.py)

`generate_authority` (destruction_provision.py:40-62): mints one owner key + N co-signer keys, an m-of-n `TrustRoot` at `threshold` (fail-closed on threshold outside `1..n`), owner bound mandatory. `sign_action` (destruction_provision.py:65-97): owner (+co-signers) sign ONE `DestructionAuthorization` with window `[now-30, now+window_s]`, **fail-closed if the window exceeds the 900s dead-man's-switch limit**, blank nonce/action_id/target refused. Co-signer keys are read from FILES not argv (`load_worker_key_file`, destruction_provision.py:107-125) so they never land in the process table. **Honest security model (destruction_provision.py:14-20): threshold=1 solo-owner is single-use+window+action-bound but is NOT separation of duties** — real m-of-n protection requires co-signer keys on *different* machines.

### The LOCAL terminal: `execute_terminal` (executor.py:1035-1146)

A DISTINCT executor path — reuses the same gate + signed-record machinery but SKIPS network target-pinning, because the egress floor is preserved **by construction**: the allowlist admits ONLY local, non-network, non-interpreter, non-writer read/inspect binaries (executor.py:716-782). Order (fail-closed): (0) no signer → refuse; (1) `_parse_terminal_pipeline`; (2) confine `cwd` (`_safe_terminal_cwd` refuses `..`/NUL/non-dir, executor.py:1020-1032); (3) **construction invariant** — `_terminal_warden_tier()` must be A2/A3, never auto (fail-closed to A3 on classifier-import failure, executor.py:833-844); (4) `authorize_tool_call` scoped on `127.0.0.1`; (5) run; (6) signed record. The record's tier is overridden to the WARDEN classification (A2/A3) so the "never auto" property is visible on the spine (executor.py:1118-1121).

Allowlist model (executor.py:752-943): pure read/print binaries (`ls cat grep cut tr od hexdump base64 sha256sum find sort uniq file date hostname …`) are admitted; **every network binary (curl/wget/nc/ssh), interpreter (bash/python/awk), and writer (tee/cp/rm/sed -i) is absent → DENIED.** A red-pen proved a spelling *denylist* can't be complete (GNU getopt_long accepts prefix abbreviations `--out=`≡`--output`; `xxd -r` writes a file — excluded), so capable binaries are ALLOWLISTED via `_terminal_binary_guard` (executor.py:889-943): `find` via a read-only PREDICATE allowlist `_FIND_SAFE_PREDICATES` (exec/write predicates `-exec/-delete/-fprint*` refused by OMISSION); `sort`/`uniq` via read-only FLAG allowlists `_SORT_SAFE_FLAGS`/`_UNIQ_SAFE_FLAGS` (uniq also refuses a 2nd file operand = its output write); `file` `-C`/`--compile` refused; `date`/`hostname` admitted BARE only. *(These flag-allowlist guards are previously undocumented in the feature docs.)* `_TERMINAL_METACHARS` (`; & | > < \` $ ( ) { } \n \r NUL \\`) refuse the whole command; split is ASCII-whitespace only, no shell ever consulted (executor.py:822-886). **Pipelines** (`A|B|C`) are supported via `_parse_terminal_pipeline` (executor.py:950-981): the `|` is split here (never a shell), each stage validated by the same single-command parser, `_MAX_PIPELINE_STAGES=8`; `_run_pipeline` (executor.py:984-1017) runs stages SEQUENTIALLY feeding stdout→stdin with `_PIPELINE_INTERMEDIATE_CAP` (8 MB) and per-stage timeboxing. *(Pipeline internals previously undocumented.)* `TerminalRuntime`/`build_terminal_runtime` (wiring.py:620-684) is the minimal gate+sealed-signer subset for the standalone `vigil` terminal verb — `gate=None`→deny-all, `signer=None`→refuse.

### The bwrap sandbox tier: `execute_sandbox` + `sandbox_exec` (executor.py:1163-1256, sandbox_exec.py)

Runs an **ARBITRARY** command (`/bin/sh -c`) made safe by KERNEL isolation, not an allowlist. `execute_sandbox` (executor.py:1163-1256): (0) no signer → refuse; empty command / no workspace → DENY; (1) construction invariant `sandbox.exec` must classify A2/A3 (it's A3, executor.py:847-855); (2) `authorize_tool_call` scoped on `127.0.0.1` (A3 → queues under the A1 ceiling → owner-approval / M2 token leg); (3) run in the isolated box — **a missing bwrap or unsafe workspace is a DENY, NEVER an un-sandboxed run** (`SandboxUnavailable`/`ValueError` → deny, executor.py:1226-1236); (4) signed record. *(Note: `execute_sandbox`/`run_sandboxed` are the live sandbox entry but `execute_sandbox` is NOT in executor's `__all__`, executor.py:75.)*

Isolation model (`sandbox_exec.py`): `_BWRAP_BASE_FLAGS` = `--unshare-all --die-with-parent --new-session` + a MINIMAL read-only bind allowlist (`/usr /bin /sbin /lib* /etc`) + `--proc --dev --tmpfs /tmp` (sandbox_exec.py:56-67). Two floors are kernel-enforced: **NO EGRESS** — `--unshare-all` unshares the network namespace (the load-bearing NET unshare covers IP + abstract unix sockets); **NO WRITE OUTSIDE THE WORKSPACE** — the ONLY writable paths are the bound workspace (`--bind ws ws --chdir ws`, appended per call by `build_bwrap_argv`) and the ephemeral `/tmp` (sandbox_exec.py:105-110). **The host-socket escape it avoids (a red-pen BLOCK, sandbox_exec.py:12-17):** it deliberately does NOT `--ro-bind / /` — a wholesale root bind carries the host `/run` and its daemon sockets (`/run/docker.sock` = host-root-equivalent, D-Bus) into the box; pathname unix sockets live in the MOUNT namespace so `--unshare-*net*` does NOT isolate them, so no `/run`,`/home`,`/var` is bound and no host socket exists in the box at all. Documented residuals (reviewed, not escapes): read-only `/etc` disclosure (`/etc/shadow` is mode-640 + unreadable + no egress to exfil) and a host-side workspace-path TOCTOU out of the in-box threat model (sandbox_exec.py:19-23). `_safe_workspace` refuses a symlinked/non-dir/unresolvable workspace (sandbox_exec.py:89-102). `run_sandboxed` (sandbox_exec.py:142-172) is **fail-closed with NO fallback** — bwrap missing → `SandboxUnavailable`.

### The live engine loop: `VigilEngine.engage` (engine.py:173-303)

A single attestation-first OODA loop over injected `EngineSeams` (engine.py:94-111), each `None`-seam fail-closed at its point of use. Flow:

- **(0) ATTEST FIRST** (engine.py:180-186): no attestation seam under `require_attestation` → the whole run is REFUSED; an attestation error or `allowed is not True` → refused (`_attest_run`, engine.py:307-322).
- Per iteration: `_drain_operator` folds advisory operator instructions into state (never a tool trigger, engine.py:363-376); `_think` proposes an `LLMDecision` (a think error → the *safest* ASK_USER, never an action from noise, engine.py:324-336). `COMPLETE`/`ASK_USER` are inert terminals (ASK_USER is resumable if an instruction was queued, engine.py:200-213).
- **`authorize_edge(decision, state, gate=seams.gate)`** (engine.py:215, react.py:155): `"queue"` → the human leg — proceeds only if `_approved` (a signed operator approval; None-seam → False → stays queued, engine.py:218-228, 355-361); a non-`allow` non-`queue` → recorded denial + PIVOT (never gives up the run, engine.py:240-246).
- **Execute** through `_run_tool(decision.tool, phase, seq, approved=…)` (engine.py:249, 338-353) — the executor re-checks the gate itself (defence in depth). A non-`ran` result → recorded refusal + emit/checkpoint (engine.py:252-261).
- **Terminal advisory rule** (engine.py:263-277): a `terminal.run` record's output is ADVISORY-ONLY and **never enters oracle intake** — an autonomous terminal command can never mint a FACT (still emitted + checkpointed for audit).
- **Oracle intake** (engine.py:279-292): the LLM's claims are LEADs; only `seams.oracle` re-firing over the RAW `stdout` mints a signed FACT (`intake_result`, react.py:221). Then project (FACT-only) / govern (advisory) / emit / checkpoint.

How the loop drives tools within a latched capability (`run_tool`, wiring.py:339-369): the active gate is the `approval_gate` (M2 token path or standing-boolean upgrade) when `approved` and available, else the base `gate` — either way CRUCIBLE scope + the loopback pin still gate every call. A `terminal.run` decision routes to `execute_terminal` (no argv builder in the network `execute` path — it would be denied as "unknown tool"); everything else to `execute` with the `offense_scope` egress source threaded.

### The wiring oracle seam — LEAD-only, honest (wiring.py:687-723)

`_build_oracle` passes the LLM's `analysis.extracted_info['oracle_context']` with **`provenance="llm"`** so `confirm_and_certify` runs the deterministic oracle (the LEAD is honestly labelled with what fired) but **never signs an LLM-provenanced context into a FACT** — closing the AUDIT-G4 anti-hallucination route. Minting a FACT requires reproducing the finding from the executor-captured `raw_output` (`provenance="reproduced"/"live_redrive"`), which is the **documented follow-up, not yet wired** — until it lands this seam yields LEADs, the correct fail-closed disposition (wiring.py:687-699). An oracle/cert error confirms nothing (wiring.py:719-721). Optional `project`/`emit`/graph seams are honestly omitted (returned `None`) when Neo4j/OTLP are absent — a graph/telemetry outage never affects the run's truth (wiring.py:16-19, 465-494).

## 4. Oracles, the veracity firewall and the proof pipeline

The system's one invariant: **a claim is a FACT only when a deterministic, pure oracle re-fires over bytes a real target produced.** The LLM (Strix) only *proposes*; every promotion is a re-execution, never a string-trust. This section traces a proposal all the way to an oracle-confirmed, m-of-n-signed, offline-verifiable, transparency-anchored FACT, and documents the layer that can only ever *demote*.

Two code homes: the offense engine `engine/crucible/framework/v2/{verify,evidence,confidence,report,agents}` (env-offense, keyless), and the integration glue `integration/vigil_integration/{oracle_adapter,challenge_oracle,scitt,transparency,proof/bundle}.py` (import-clean, `framework.*` imports lazy so the sovereign env never co-loads it — FATAL-2, e.g. `oracle_adapter.py:108-111`).

### The oracle purity contract

Every oracle in `engine/crucible/framework/v2/verify/oracles.py` is **pure, deterministic, side-effect-free** (`oracles.py:4-9`): it reads already-collected evidence, judges, returns an `OracleSignal(kind, fired, confidence, evidence, observed)` (`verify/models.py:248-269`) — it never sends. Same inputs → same signal, every time. Intra-oracle confidence combines corroborating dimensions with a **noisy-OR clamped to 0.99** (`_noisy_or`, `oracles.py:179-185`) so "a deterministic oracle never claims certainty it cannot have." An absent/negative signal is *never* an assumed pass (fail-closed). The one stateful sibling that is *not* a pure oracle is `verify/oob.py`, the out-of-band **receiver** that mints the per-finding correlation token `oob_callback_oracle` later judges — a collector, cited as the exception in the `OracleKind` docstring (`models.py:34-36`).

### The full oracle catalog (`OracleKind`, `verify/models.py:31-214`)

`OracleKind` has **32 members**. The first 15 form the frozen unknown-class fallback `_ALL_ORACLES` (`verifier.py:445-461`, verified exactly 15 members); the remaining 17 are ADDITIVE appends reachable **only** via an explicit `BUG_CLASS_ORACLES` row (never the fallback), firing only when the context carries a class-specific key no benchmark/scan/engage finding carries — so `make gate` stays byte-identical. For each: what it deterministically checks and its negative control.

**Core 15 (`_ALL_ORACLES`):**

1. **DIFFERENTIAL_RESPONSE** — `differential_response_oracle` (`oracles.py:193-297`). Quantifies divergence between a baseline and a mutated response across `{status, length, lexical, structural, latency, marker}` dimensions, each weighted, combined by noisy-OR. Structural dim uses an AST signature (JSON path-type set / HTML tag-path multiset, `structural_diff` `oracles.py:155-176`) **invariant to nonce/CSRF/timestamp noise** but sensitive to an added record — that is the negative control (a page merely reflecting a per-request token does not read as a diff). Supports `expect:"same"` for indistinguishability. Boolean/time-based blind SQLi.

2. **ACHIEVED_STATE** — dispatched to two functions. `predicate_oracle` (`oracles.py:653-679`) evaluates a declarative JSON predicate AST (ops confirmed `all/any/not/eq/ieq/contains/icontains/in/min_len/gt/ge`, `_eval_predicate` `oracles.py:610-650`) over *raw observed values* — the fix for the "rubber-stamp" where a check passed its own boolean; here the oracle judges the actual header/body/status values. `achieved_state_oracle` (`oracles.py:682-715`) fires only on a **full** match of a non-empty expectation; a partial match is informational (does not fire). Backs idor/bola/bfla/broken-access/CORS/host-header/open-redirect/jwt/graphql/business-logic/SSO-acceptance/etc. (dispatch `verifier.py:638-647`).

3. **SIDE_EFFECT** — `side_effect_oracle` (`oracles.py:731-760`). A unique attacker marker (≥4 chars, negative control against incidental substrings) surfaced in a sink it must never reach.

4. **OOB_CALLBACK** — `oob_callback_oracle` (`oracles.py:1439-1459`). ≥1 inbound interaction on a per-finding unique correlation token = near-unforgeable blind-execution proof (SSRF/OOB-SQLi/blind-XXE/deserialization). No hit → no fire. The token is minted by the stateful `verify/oob.py` receiver, not the oracle.

5. **SANITIZER_SIGNAL** — `sanitizer_signal_oracle` (`oracles.py:1284-1309`). Regex catalog (`_SANITIZER_PATTERNS`) over captured stdout/stderr: ASAN/MSAN/TSAN/UBSAN/LSAN, stack-smashing, glibc abort, Rust/Go panic, SIGSEGV, and a *bare Python traceback only at 0.65* (can be a handled error — the negative control). Strongest match wins.

6. **TIMING** — `timing_oracle` (`oracles.py:368-473`). A **real hypothesis test**, not a fixed threshold: (1) one-sided **Mann-Whitney U** rejects H0 at α (distribution-free, tie+continuity corrected, `_mann_whitney` `oracles.py:333-357`); (2) a **Hodges-Lehmann** median-shift effect floor (≥0.5×injected delay or 250ms) rejects statistically-significant-but-tiny drift; (3) optional **dose-response** — the shift must *scale* with injected delay (a constant offset gives ratio ~1.0 and is refused, `oracles.py:429-437`). Needs ≥5 samples/arm. Wired via ctx `baseline_latencies`/`treatment_latencies` (`verifier.py:621-629`).

7. **BOOLEAN_INFERENCE** — `boolean_inference_oracle` (`oracles.py:514-576`). Wald **SPRT** (`_sprt_decision` `oracles.py:476-511`) over probe rounds; per-round Bernoulli = `(TRUE differs from FALSE) AND (the two FALSE responses agree)` — the second clause is a **dynamic-page control** so a page that changes every request trips the control and cannot masquerade as a bug. Confirms at LLR ≥ log((1-β)/α); no boundary = inconclusive (a non-fire, never a guess).

8. **REFLECTION_CONTEXT** — `reflection_context_oracle` (`oracles.py:812-863`). Parses the response (stdlib `HTMLParser`, `_ReflectionScanner` `oracles.py:768-809`) and fires only when a marker reached an **executable** position (became a tag name, inside `<script>`, or an `on*`/`javascript:` attribute). `convert_charrefs=True` means an HTML-encoded payload arrives as inert TEXT and correctly does **not** fire — the precision win over substring XSS.

9. **EVALUATION** — `evaluation_oracle` (`oracles.py:871-934`). SSTI/EL: fires only when (1) the computed `expected_result` appears, (2) the raw expression does **not** survive verbatim (else it was reflected, not evaluated), and (3) — with a control body — the result is absent from the benign control. All three guards are negative controls.

10. **ERROR_SIGNATURE** — `error_signature_oracle` (`oracles.py:1398-1431`). ### The verifier — routing, threshold, combine policy (`verify/verifier.py`)

`BUG_CLASS_ORACLES` (`verifier.py:33-242`) maps ~80 canonical bug classes (+ `_ALIASES` `verifier.py:245-435`) to their acceptable oracle tuples. `OracleVerifier.confirm(ctx)` (`verifier.py:557-611`) runs each oracle whose inputs are present (`_run` dispatch, `verifier.py:613-802`), then applies **any-high-confidence-fired** (`HIGH_CONFIDENCE = 0.7`, `verifier.py:25`): confirmed iff ≥1 oracle `fired AND confidence≥0.7` (`verifier.py:587-588`). Policy is **safety-monotone** — a non-firing oracle cannot veto a fired one; it is recorded as `dissent`, not a refutation (`verifier.py:590-600`). `confirm_finding` (`confirmation.py:102-150`) promotes to a `ConfirmedFinding` (whose *type is the proof* — it only exists when an oracle fired) or `None`. The reproducible negative-control artifact: `confirm_against_local_target` (`confirmation.py:273-311`) stands up a real loopback SQLi app (`DifferentialDemoHandler` `confirmation.py:235`) and confirms; pointed at `SafeDemoHandler` (parameterised twin, `confirmation.py:241`) it returns `None` — proving the authority does not rubber-stamp.

**Value-membership (anti-hallucination P6):** `known_bug_classes`/`is_known_bug_class`/`require_known_bug_class` (`verifier.py:482-535`) reject an out-of-vocabulary class at pydantic parse time (`KnownBugClass = Annotated[...]` field type, `verifier.py:543`) so an *invented* class can't be asserted oracle-provable. `oracle_confirms_class` (`verifier.py:511-522`) is the PCF step-5 relabelling defense (an oracle that doesn't confirm class X can't stamp a class-X claim).

### Re-verification — retained context, DEMOTE-only, tamper detection (`verify/reverify.py`)

Every confirmed finding retains the exact evidence the oracle judged as a serialized `FindingContext` (`oracle_context`). `reverify_context` (public wrapper `reverify.py:95-120`, impl `_reverify_context_impl` `reverify.py:123-184`) reconstructs it, re-runs the pure oracle, and confirms the verdict reproduces *and matches the claimed `confirmed_by`/`confidence` within 1e-6* (`_CLAIM_EPS` `reverify.py:36`, checked `reverify.py:173-176`) — a mismatch is flagged "tampered?". **Binding is load-bearing:** the evidence adjudicates its OWN bug_class; a requested class that differs from the evidence's class is REFUSED at the re-execution boundary (`reverify.py:152-158`) so a relabelled finding (sqli evidence → 'rce') can't re-confirm as the flip. Memoized on canonical evidence JSON (`_cache_key`/`_reverify_cached` `reverify.py:65-92`; determinism-safe — can only elide an identical recompute, always returns a fresh copy). `python3 -m framework.v2 verify <report.json>` (`main` `reverify.py:218-245`) exits 0 iff **every** certificate reproduces and matches its claim, else 2 — turning the whole output into independently re-executable proofs with no target and no trust in the tool.

### The veracity firewall — the DEMOTE-only choke point (`veracity/firewall.py`) — SCAFFOLDED/PHASED

`admit(claim)` (`firewall.py:105-181`) turns a `Claim` into an `AdmittedClaim` by **re-executing each cited ground**, never trusting a string, and labelling `CONTRADICTED` / `UNGROUNDED` / `GROUNDED(fact|hypothesis)`. Decision order: (1) world-model contradiction refutes a named entity (`contradicts`, `firewall.py:116-120`); (2) a named entity absent from the graph → UNGROUNDED (fabricated target, `firewall.py:122-128`); (3) validate each ground *bound to this claim's subject* — an ORACLE token must **re-fire for the claim's OWN bug_class** (`_oracle_ok` calls `reverify_context`, `firewall.py:50-63`), a CERT must certify that class (`_cert_ok`, `firewall.py:66-79`), a WORLDMODEL node must be one the claim names AND belief-LCB-floored (≥0.5, `_BELIEF_FLOOR` `firewall.py:40`) with provenance tracing to a real oracle/cert (`_worldmodel_ok`, `firewall.py:82-93`); (4) a `from_dryrun` claim can stand only on re-executable oracle/cert grounds (`resolved &= {ORACLE, CERT}`, `firewall.py:154-155`), never its own LLM reasoning; (5) label — the calibrated confidence of a fact is the **re-executed** oracle value, not a proposer number (`firewall.py:168-169`). **The layer only ever DEMOTES or abstains** — it can turn a fabricated "confirmed" into UNGROUNDED but can never promote a claim the oracle refused; a dry-run-backed token cannot ground.

**Honest phasing (label carefully):** `firewall.py:27-30` states this is the caller-less **PRIMITIVE** (veracity P0); runtime enforcement (the world-model admission gate P2, the reporting gate P4) is "wired in the subsequent phases… until then admit() is exercised only by its tests; that is by design, not a gap." It is NOT today a universal live choke point every claim crosses.

### Confidence engine — non-invasive, does not override the oracle (`confidence/`)

`assess` (`engine.py:92-152`) turns a `ScientificHypothesis` (focal + MECE alternatives + residual) into a posterior distribution via log-scores `ln(prior) + Σ(weight×independence×ln LR)` (`_logscore` `engine.py:50`) and a numerically-stable softmax (`_softmax` `engine.py:54`), a Beta credible interval that tightens with evidence count (`_credible_interval` `engine.py:61`), and an internal next-observation selector — `_value_of_next_evidence` (`engine.py:72`) — that ranks the single most decisive next observation by expected information gain. `assess_finding` (`decision.py:68-113`) enters the oracle confirmation as evidence with a likelihood ratio (oracle **60×** `decision.py:34`, ×1.5 with a replayable cert; passive 2×) against the specific benign twin each class masquerades as (`_ALTERNATIVES` `decision.py:44-58`). Explicitly **non-invasive** (`decision.py:11-16`): the oracle stays the sole confirmation authority; this only expresses *how confident* that confirmation leaves us.

### From proposal to signed FACT — the adapter pipeline (`integration/vigil_integration/oracle_adapter.py`)

`confirm_and_certify` (`oracle_adapter.py:81-164`) is the headline pipeline for one proposed finding carrying its retained `oracle_context`: (1) `confirm_finding` re-runs the deterministic oracle — `None` unless one fired at ≥0.7 (no assertion path, `oracle_adapter.py:116-122`); (2) **honesty invariant** — a signed FACT also requires the class to be oracle-mapped (`is_known_bug_class`), else a labelled LEAD (`oracle_adapter.py:124-133`); (2b) **provenance gate (audit G4)** — a signed FACT also requires `oracle_context` provenance ∈ `{reproduced, live_redrive}` (`_REPRODUCED_PROVENANCE` `oracle_adapter.py:48`, enforced `oracle_adapter.py:139-147`); the DEFAULT `"llm"` (the model's own `extracted_info`) is demoted to a LEAD even when the oracle fires, because a crafted-but-firing context is an LLM-influenced route to a FACT; (3) only then mint + m-of-n sign an `EvidenceCertificate` (`oracle_adapter.py:149-158`). Refuses to mint with zero signers (fail-closed, `oracle_adapter.py:103-107`). **The live re-drive of a scope-gated target is explicitly DEFERRED** — "a documented refinement for a later slice… needs a live target + the egress gate" (`oracle_adapter.py:30-34`). `certify_to_scitt` (`oracle_adapter.py:167-194`) refuses a non-fact (a lead has no signed cert to call 'affected').

### Challenge oracles — replay/hallucination *impossibility* (`integration/vigil_integration/challenge_oracle.py`)

Generalizes DARPA CGC's proof-of-vulnerability to every web class: each confirmation issues a **fresh unpredictable 128-bit challenge** (`secrets.token_hex(16)` `challenge_oracle.py:52`, `_MIN_TOKEN_LEN=16` enforced `challenge_oracle.py:55-59`); the finding is VERIFIED only if the live target satisfies THAT token — a recorded or LLM-invented response for an old token always ABSTAINs. Four oracles: `NonceEchoOracle` (SQLi/XSS/SSTI, `:85`), `CanaryLeakOracle` (IDOR/LFI, `:95`), `OOBTokenOracle` (SSRF/blind RCE/XXE, `:105`), `ValueControlOracle` (memory-safety, `:118`). **Kernel-minted epistemics (EG-VAR):** only the oracle can MINT a `Verified` verdict — HMAC-bound to the challenge under a per-run oracle key (`_mac` `challenge_oracle.py:143-150`, `mint` `:153`), so no LLM/critic can forge it; downstream trust requires `verify_minted` (`challenge_oracle.py:163-168`). The value is `Verified | Abstain`, never a bare boolean an agent could assert.

### Evidence certificate — the cryptographic spine (`evidence/certify.py`)

`build_certificate` (`certify.py:53-91`) binds `oracle_context_digest` (sha256), a per-file `artifacts` manifest, optional `report_claims`, and the **oracle `id@version`** stamped at mint (`oracle_version(kind)` `verify/oracle_version.py:82-99` — a `sha256:<hex>` over the pure oracle function's canonical source, so any body change is detectable; empty string on a source-less frozen deploy → PCF reports it cannot confirm the version, `oracle_version.py:6-18`). `sign_certificate` (`certify.py:111`) is provisioning-only (governance authorisers, m-of-n); the runtime only verifies. `verify_certificate` (`certify.py:171-215`) checks **five independent layers**, all required for `ok`:
1. **Authenticity** — m-of-n Ed25519 threshold over canonical bytes.
2. **Binding** — `sha256(oracle_context) == cert.oracle_context_digest` (a signature can't be lifted onto other evidence).
3. **Artifact integrity** — every manifested raw file re-hashes; **fail-closed** if artifacts are claimed but no `evidence_root` given (`certify.py:190-194`).
4. **Reproduction** — the pure oracle re-fires and matches the claim (`reverify_context`).
5. **Claims-grounded** — every `render_as=="fact"` report sentence re-admits through `admit()` bound to its declared class (`_claims_grounded` `certify.py:139-168`); a relabelled claim fails closed. Honest scope: this checks the declared CLASS re-executes, not NL entailment.

`verify_bundle` (`certify.py:284-337`) binds the certificate SET to the hash chain (chain digests == finding-then-path cert digests, in order — no suppression/injection/reorder), applies the monotonic anti-rollback high-water on the governance-signed head, and requires each derived **path certificate** be anchored by a *valid signed head* AND backed by finding certificates that themselves verified (`_verify_paths` `certify.py:255-281` — path certs aren't individually signed, so the signed head is their only anchor).

### PCF — Proof-Carrying Findings v0.1 (`evidence/pcf.py`)

`to_pcf` (`pcf.py:91-104`) projects a `SignedEvidence` into the open PCF wire format, embedding the authoritative signed certificate + the retained `oracle_context` value (PCF "complete"). `verify_pcf` (`pcf.py:121-225`) runs PCF §6's five ordered fail-closed steps, each delegating to a real primitive: (1) schema+vocabulary (`require_known_bug_class`); (2) m-of-n signature over domain-separated bytes PLUS a **faithful-projection check** — the presented view must equal the view re-derived from the signed cert field-for-field (`_project_view` `pcf.py:57-88`), so no field can be mutated into a lying wrapper; (3) evidence-digest integrity + artifacts; (4) oracle reproduction PLUS **`id@version` staleness** (the oracle body must be unchanged since issue); (5) claim-grounded (`oracle_confirms_class`). Rejects fail-closed on absent trust root (ungoverned).

### The client-verifiable proof bundle (`integration/vigil_integration/proof/bundle.py`)

`export_bundle` (`bundle.py:96-200`) writes a self-contained directory a third party verifies **offline with zero trust in VIGIL**: `evidence-bundle.json` (signed certs + chain + signed head), `trust-root.json` (public keys only), `reverifiable.json` (each finding's `oracle_context`), the raw `evidence/<action_id>/…` bytes, `TRUST-ROOT-FINGERPRINT.txt`, and a README with the one-command verify. Only oracle-confirmed FACTs are bundled (`bundle.py:113-116`). **Authenticity anchor is the OUT-OF-BAND fingerprint pin** (`--trust-root-fingerprint`): the shipped `trust-root.json` is only a convenience copy — without the pin, exit 0 proves internal consistency + reproduction but NOT authenticity. Security hardening: the file-supplied `action_id` is confined to a single in-tree path segment (`bundle.py:128-131`); evidence is copied with **symlinks never followed or shipped** (`os.walk(evidence_root, followlinks=False)` `bundle.py:170`, per-file `is_symlink` skip) — the root-cause fix for a prior copytree-dereference exfil BLOCK; all writes are 0600/0700 (`_secure_write` `bundle.py:87`).

> Adjacent (a sibling capture layer, not the deterministic-proof core): `proof/{content_gate,minimize,sink,engine,run}.py` are the live Strix-PoC capture/minimization modules that *produce* the `oracle_context` the pipeline above re-executes. They are not oracles and hold no adjudication authority; the oracle remains the sole judge of the bytes they capture.

### The dossier zip — everything, tamper-evident (`report/dossier.py`)

### SCITT / OpenVEX / DSSE / RFC-6962 receipt (`integration/vigil_integration/scitt.py`)

### Transparency — witnessed checkpoints, split-view resistance CONDITIONAL (`integration/vigil_integration/transparency.py`)

A `Checkpoint` (`transparency.py:58-90`) is a public summary of a signed spine head (last_seq, entry_count, head_hash, merkle_root, prev_checkpoint_hash). A `Witness` (`transparency.py:125-167`) countersigns only after verifying `consistent` (`transparency.py:103-116`: append-only — no count shrink, no seq rollback, chain-link intact, no same-height fork), so an honest stateful witness never equivocates. `CheckpointEmitter` (`transparency.py:174-231`) maintains the meta-chain, is idempotent on an unchanged head, and gathers countersignatures ATOMICALLY (decide the willing set with no mutation, then co-sign) so a desynced witness is skipped not fatal.

**Split-view resistance is CONDITIONAL, not automatic** (`transparency.py:11-26`, `234-283`): `verify_witnessed` (`:234`) proves a quorum signed; PREVENTION additionally requires `is_split_view_resistant` (`:244`) — a **strict majority** `2*threshold > n` over **distinct** keys (deduped over the decoded 32-byte key; `load_public_key` rejects non-canonical y≥p and low-order Ed25519 points that admit a keyless forgery). Below strict majority (in particular the trust-model-blessed `threshold==1`), two disjoint quorums can each sign a different fork with no witness equivocating — only per-witness non-equivocation and after-the-fact **detection** (`is_split`, `transparency.py:301-314`, keyed on `head_hash` so a benign re-prune isn't falsely flagged) remain. A `MultiSegmentCheckpoint` (S7c, `transparency.py:346-435`) composes every spine segment's tip into one witnessable object so a fork in ANY segment — or a segment silently added/dropped — breaks consistency (`multi_consistent` `:388`); `verify_split_view_resistant_multi` (`:428`) extends the guarantee to the whole S5 view. OpenTimestamps Bitcoin anchoring is a **DEFERRED** external-service refinement (needs a live calendar server).

### Spine chain — content+order tamper-evidence (`agents/spine_chain.py`)

`build_spine_chain`/`verify_spine_chain` (`spine_chain.py:80-98`) hash-link every event (deterministic `event_digest` over kind/agent/payload/parent/supersedes + `engagement_id`, **excluding wallclock**, `spine_chain.py:38-51`), reusing the evidence layer's chain primitives. ### The Verifiable-Fact program — a remediation is a re-verifiable FACT (`integration/vigil_integration/remediation/` + `docs/proof-carrying-finding/`)

The proof pipeline's negative dual: it proves *"this bug is really fixed"* by re-execution, to the same standard as a positive FACT. Prose: [`../knowledge/kb/verifiable-fact.md`](../knowledge/kb/verifiable-fact.md); decision record: [`../knowledge/decisions/0002-verifiable-fact-program.md`](../knowledge/decisions/0002-verifiable-fact-program.md); specs: [`proof-carrying-finding/{REMEDIATION-SEMANTICS,PROTOCOL,WITNESS-TRUST,TRUST-GRADIENT,DIFFERENTIAL-REMEDIATION}.md`](proof-carrying-finding/). Built & merged: 18 impl PRs **#186–#202**; design spec **#203**. Every crypto/composition slice red-penned to convergence.

- **RemediationCertificate — the negative proof (`remediation/remediation_cert.py`).** A portable, m-of-n-signed cert earned by the original exploit oracle re-firing on the patched build then going **SILENT** (`_is_silent`/`_fires`). Controlled by construction: the positive-control twin must still FIRE, the target must have answered (liveness), and the whole cert is signed so no control can be stripped. The negative-proof state machine (UNKNOWN → EXPLOITABLE@T → REMEDIATED@T′ → REGRESSED / INDETERMINATE) is `REMEDIATION-SEMANTICS.md`; the 13-vector MUST-ACCEPT/MUST-REJECT conformance corpus is `integration/tests/test_remediation_conformance.py`.
- **The four-state prove-driver (`remediation/prove_driver.py`).** The `vigil remediate --prove` orchestrator: REMEDIATED / STILL_VULNERABLE / INCONCLUSIVE / REFUSED, a causal-chain freshness challenge, an immutable `EffectiveAuthorization` + atomic budget, identity sampled 4×, downgrade resistance (no skip flags), and the F0–F4 freshness gradient. Certifiability is DERIVED from `canonical_bug_class` + the oracle taxonomy as a **fail-closed allowlist** (deterministic-per-observation kinds only; timing/race/cred-stuffing/prompt-injection/unknown → REFUSED). `verify_prove_certificate` re-executes the embedded cert and checks the whole-cert signature + cross-binding (finding/class/nonce/digest).
- **Freshness F0–F4 + the firing-only F2 gate (`prove_driver.py` `Freshness`, `_challenge_in_firing_signature`).** F2 is credited ONLY to a FIRING trial whose fresh challenge is reflected in the matched datastore-error LINE (the helper calls the `error_signature` oracle itself to locate the match, then checks same-line containment) — a SILENT trial caps at F1, because reflection is not sink-traversal (an echoer/edge would fake it). VF-1a.3 (#202) fixed a #192 overclaim that credited F2 to a silent verdict; the honest boundary — "as attributable as the oracle's own firing, NOT byte-unforgeable" — is stated in the enum, the docstrings, and `TRUST-GRADIENT.md`.
- **The live-HTTP re-drive adapter (`remediation/live_adapter.py` `LiveHttpAdapter`).** Re-drives the original exploit through the gated `HttpExecutor` against a live target (gate ENFORCED, not bypassed) and turns the fresh bytes into the exact `oracle_context` the original oracle re-fires over. `payload_template` (`str.replace`, literal-brace-safe) weaves the run challenge into the exploit payload for genuine F2; `run_positive_control` is a REAL gated fetch this run (VF-1a.3), with `injectable_param_live` recorded as an informational-only signal (a reflected marker may be the app OR an echoing edge — it never gates a verdict). Tests: `test_live_adapter.py`, `test_live_adapter_f2.py` (real loopback servers: vulnerable/patched × reflect × WAF × param-strip), `test_prove_driver.py`.
- **Identity + capability + proof-of-possession (`packages/core/vigil_core/vigil_core/capability.py`).** `IdentityAttestation` (owner-attested acceptable-identity policy; `identity_matches` = conjunctive-over-dimensions / any-of-within → anti-transplant), `Capability` (owner-minted, identity-bound, class-allowlisted, windowed, rate-limited, revocable, biscuit-style **narrow-only attenuable**), and `WielderProof` proof-of-possession (the wielder signs a fresh caller challenge bound to the capability digest with the *audience private key* — an authz binding over a value in the bearer's own bytes proves nothing). Observed-TLS-SPKI target binding via `framework/v2/verify/tls.py` `tls_spki_sha256` (HTTPS-strong; HTTP → host-only, never fabricated).
- **Continuous Attestation Log + anti-rollback floor (`remediation/attestation_log.py` + `vigil_core/highwater.py`).** Each re-proof tick is appended to a signed hash-chain guarded by a durable high-water floor (entry-count primary guard, upward-only under flock, corrupt → fail-closed), yielding a monotonic series `present → proven-fixed → still-proven / regressed`. `verify_log` loads the floor FIRST so a full truncation (empty log + floor > 0) is caught as a rollback, then rebinds head↔rebuilt-chain and re-verifies every tick.
- **Witnessed, no-later-than-T checkpoint (`remediation/attestation_witness.py`).** A timed layer atop the merged transparency primitives: each witness folds its observed time into a sig under a distinct domain tag; `verify_timed_witnessed` runs the strict-majority split-view-resistant gate, per-sig verify with malformed-sig tolerance, distinct-verifying ≥ threshold (raisable via `min_distinct_signers`), and a median no-later-than-T. Honestly *strictly weaker* than non-equivocation — the bound is over the presented signing quorum.
- **The OOB dishonest-producer tier (`framework/v2/verify/oob.py`, `oracles.py`).** For out-of-band-observable classes: `oob_callback_oracle(hits, expected_token, collector_pubkey)` fires only on a registered per-finding token match (constant-time `hmac.compare_digest`) AND, when a collector key is pinned, a verifying receipt over `{token, client_ip, received_at, method, path}` signed by an INDEPENDENT collector whose key is pinned OUT-OF-BAND. A producer without the collector key cannot forge a verifying receipt.
- **The standalone VIGIL-free verifier (`docs/proof-carrying-finding/verify_vf.py`).** Python stdlib + one Ed25519 lib; `--prove-standalone` asserts no VIGIL module is even importable. Re-derives the whole lifecycle offline (remediation cert → attestation series → witnessed timed checkpoint) with byte-parity to the real serializer against out-of-band-pinned trust roots; a single flipped byte flips it to NOT SOUND. Documented boundary: it checks signatures/binding/structure/chain/quorum but **never re-fires the oracle** (that layer needs VIGIL), and no standalone output prints "remediated/silent". Differential test: `integration/tests/test_vf_differential.py`.
- **The end-to-end lifecycle demo (`integration/tests/test_vf_end_to_end.py`, #201).** One test against a real loopback target: vulnerable → STILL_VULNERABLE, patched → REMEDIATED (live re-drive, F1), re-proved, `verify_log` series `present → proven-fixed → still-proven`, a 2-of-3 witness quorum → no-later-than-T, then the standalone `verify_vf` confirms the whole bundle and REJECTS every tamper (flipped state / truncated tick / dropped witness sig).
- **`TRUST-GRADIENT.md` — the three tiers stated on the tin (#201).** Tier 1 (honest producer) with each property's enforcing code + the assumption that breaks it + its honest limits; Tier 2 (dishonest producer, OOB classes); the deferred frontier NEVER claimed active. An adversarial review caught and fixed a real overclaim *in this doc itself* (TLS-SPKI stated universally; the code delivers it only for HTTPS).
- **Differential remediation — DESIGN-FIRST, DEFERRED (`docs/proof-carrying-finding/DIFFERENTIAL-REMEDIATION.md`, #203).** A reviewed design (NO code) to narrow the silent-case interposer residual with a matched-decoy differential (a metachar-identical, data-dependent boolean pair judged by the existing `boolean_inference_oracle` + a baseline WAF-closure test + a decisive-SPRT-refute requirement). Landed spec-first so the design could be red-penned before code: the review found a false-REMEDIATED hole (an in-flight *sanitizing* WAF) and that a boolean differential is never interposer-unforgeable over plaintext HTTP, so the claims were narrowed to exactly what holds — it closes only a *blocking* WAF; sanitizing WAF / param-strip / byte-forgery are disclosed residuals. Implementation **deferred** (operator decision, 2026-08).

## 5. The knowledge engine, intel collection and memory

This domain is the part of VIGIL that *learns* — it pulls advisories, roams recon sources, resolves the asset graph, remembers cross-engagement outcomes, and drafts new capability. It lives entirely in the **env-offense** trust domain (`engine/crucible/framework/v2/{intel,knowledge_engine,memory}`). The one invariant it never breaks: **every output here is a LEAD, never a FACT.** Nothing in intel/knowledge/memory mints a fact, fires an oracle, promotes a lead, or bumps a calibrated belief on its own — only a deterministic oracle firing over bytes a real target produced does that. The recurring egress (live recon, the vuln feed, the feed daemon) is **opt-in and kill-switch-gated**; offline-with-bundled-fixtures is the default path everywhere.

The learning loop is **feed → propose → accept → deep-learn → evolve**: K1 pulls advisories as intel-tier VULNERABILITY leads (`intel/vulnfeed.py`); K2 ranks them into a propose queue (`knowledge_engine/proposals.py`); an owner-signed ACCEPT (K2b, sovereign plane) authorizes learning; K3 deep-learns FIND/DETECT/PREVENT advisory skills (`knowledge_engine/deeplearn.py`); K5 scans disclosed leads into gapped DRAFT proposals + a calibration ledger (`knowledge_engine/evolve.py`). At no step is a lead promoted or a fact minted.

### The Observation — the atomic intel datum
`intel/models.py:98` — `Observation` is the ONLY thing a collector emits and the ONLY thing that enters the world-model (via `intel/project.py`). It carries provenance (`source`/`collector`/`raw_ref`), an Admiralty `SourceReliability` (A–F × 1–6, `models.py:78`), a per-datum `confidence`, a `Polarity` (AFFIRMS/REFUTES — a REFUTES folds to `1 - confidence` truth via `truth_confidence()`, `models.py:126`), and a monotonic `seq` (never wallclock, `models.py:115`). `SourceReliability.weight()` (`models.py:89`) collapses the two axes to a `[0,1]` factor via geometric mean; "cannot be judged" (F or 6) → `0.0` (`models.py:93`), so a worthless source contributes nothing and unknown stays unknown. `IntelSourceKind` (`models.py:39`) enumerates every source: `dns, cert_transparency, rdap_whois, asn_bgp, web_archive, public_repo, vuln_db, fingerprint, operator_ingest, scan, inference, packet_capture, web_scanner, cloud_posture, misp, stix, mcp_tool`, plus the AEGIS defensive-dual LEAD kinds `request_telemetry, llm_interaction, auth_telemetry`.

**Honesty correction:** the draft claimed "every non-`scan`/non-oracle kind is inline-commented as a LEAD". The code does NOT do that. The explicit inline "a LEAD, never a fact, until an oracle re-verifies" comments sit only on `web_scanner` (`models.py:52`), `cloud_posture` (`models.py:54`), `misp` (`models.py:57`), `stix` (`models.py:58`), `mcp_tool` (`models.py:60`), and the three AEGIS kinds (`models.py:66-69`). The four passive-recon kinds (`dns`/`cert_transparency`/`rdap_whois`/`asn_bgp`) and `web_archive`/`public_repo`/`vuln_db` carry NO inline LEAD comment — their LEAD status is enforced structurally by projection (see below), not by a code comment.

### EntityRef + canonicalization
`intel/refs.py:40` — `EntityRef(kind, key)`; its `node_id` (`refs.py:50`) is exactly the world-model node id `kind:key`, so an Observation projects with no translation. `canonicalize()` (`refs.py:67`) is **total** (an unparseable value falls back to a trimmed/lowercased key, never raises): domains → punycode/lowercase (`refs.py:72`), hosts → canonical IP or hostname (`refs.py:79`), netblocks → normalized CIDR (`refs.py:84`), ASNs → `AS<n>` (`refs.py:89`), certs → hex-stripped (`refs.py:92`), CVEs → upper-case (`refs.py:97`, so the same CVE from two feeds collapses), IOC indicators → lower-cased `type:value` (`refs.py:101`). The load-bearing property is the **asset/owner tier split** (`_ASSET_TIER` `refs.py:31`, `tier` property `refs.py:54`): assets (host/domain/cert/service/app/endpoint/webapp/package) are things you attack; owners (asn/netblock/org/identity) *link to* assets via `ASSET_OWNS` and must never be merged INTO an asset cluster.

### The egress seam — the exact gate on live collection
`intel/transport.py` is the single seam between a collector and the network; a collector depends only on the `Transport` protocol (`transport.py:66`), never on httpx or the filesystem. Four implementations:
- **`DisabledTransport` (transport.py:80) — the DEFAULT.** Every `fetch` raises `CollectorEgressRefused` (`transport.py:86`). Recon egress is opt-in; a collector run with the default transport is a loud programming error, never a silent network call.
- `FixtureTransport` (`transport.py:94`) — the offline path; serves captured JSON `<source_kind>__<query>.json`. A missing fixture returns `ok=False` (not raise, `transport.py:106`), so a collector degrades to "found nothing" exactly as against a dry source.
- `MappingTransport` (`transport.py:118`) — in-memory dict for tests/embedding; a missing key returns `ok=False`.
- **`GuardedHttpTransport` (transport.py:136) — GATED live recon.** Requires a non-empty `collector_hosts` allowlist (else raises `CrucibleError`, `transport.py:159`). If `target_hosts` is supplied it calls `collector_scope_conflicts` and **refuses construction on any overlap** (`transport.py:165-176`) — recon sources must be third parties DISJOINT from target scope. At fetch time it refuses any `source_kind` with no configured endpoint (`transport.py:208`), and re-checks the actual URL host against the allowlist via `ethics.host_matches_scope` **before bytes leave** (`transport.py:216`); network/parse failures are recorded as `ok=False`, never raised past `fetch` (`transport.py:231`). The httpx client is built lazily under a double-checked lock (`transport.py:189`, X5 parallel-safety) over an `EgressAllowlist`+`SovereignHttpxTransport`. Captured responses are written owner-only via `paths.secure_write` (`transport.py:236`, X2). `CollectorEgressRefused` subclasses `SovereigntyViolation` (`transport.py:38`).

So the **loopback vs live-egress distinction** is structural: offline runs use `FixtureTransport`/`MappingTransport` (no TCP); live runs require an explicitly-constructed `GuardedHttpTransport` whose allowlist is disjoint from the target and enforced twice (construction-time overlap refusal + per-fetch host re-check).

### Collector contract + default roster
`intel/collectors/base.py:37` — a `Collector` is a pure `(subject, RawRecord) → [Observation]`. `collect` (`base.py:58`) fetches via the transport, returns `[]` on a not-ok record (never raises on a missing answer, `base.py:64`), and parses. ### Live recon wiring (crt.sh / DoH / RDAP / RIPEstat)

### IntelIngest — the single writer
`intel/ingest.py:68` — the one object allowed to mutate intel state, in fixed order: durable log → project onto world-model → resolve entities → persist entities+merge audit (`ingest.py:95`). Idempotent: re-ingesting a seen `obs_id` is a no-op that does NOT re-project (would falsely corroborate) or re-accumulate (`ingest.py:103`). `run_collectors` (`ingest.py:138`) is the recon convenience — fetch seeds through a roster (offline or gated-live), following newly-discovered subjects to a bounded `max_depth` in deterministic `(depth, node_id)` order (`ingest.py:178`). ### Projection — the keystone
`intel/project.py:35` — `project_observation` (Path A, streaming) mints subject (and object) nodes then upserts the edge with `confidence = c_eff`, letting the world-model's Beta-belief upsert handle corroboration/refutation/provenance for free. ### Co-reference signals (Fellegi-Sunter + fanout)
`intel/signals.py` — each signal contributes a log-likelihood-ratio in bits toward "same asset" (`_BASE_LLR_BITS`, `signals.py:32`: CNAME 7.0, SHARED_CERT 6.0, PRESENTS_CERT 4.5, RESOLVES_TO 3.5, SHARED_IP 2.5, SAME_NETBLOCK 0.6). The crucial rule is the **fanout discount** (`signal_llr`, `signals.py:42`). **Honesty correction (code vs docstring):** the code divides the base LLR by `1 + log2(max(1, fanout))` (`signals.py:48`), NOT by `log2(N+1)` as the module docstring at `signals.py:44` (and the draft) claims. ## 6. The sovereign plane, the two-env boundary and the host egress gate

This domain is the trust backbone of VIGIL. It answers three structural questions: (1) how the owner-key **sovereign** process and the keyless **offense** process are prevented from ever co-loading (FATAL-2); (2) how a confirmed finding crosses from offense to the owner's personal record as **inert signed data** through one gate of record; and (3) how the offense sandbox's network egress is fenced at L3/L4 and L7. Every "how it works" claim below is grounded in code I read; opt-in / deferred / conditional status is labelled inline.

### The shared integrity core — Ed25519 verify-only with weak-key rejection

`packages/core/vigil_core/vigil_core/crypto.py` is the ONE crypto primitive both envs import. `sign()` (crypto.py:140) is provisioning-only; the runtime only ever `verify_one()` (crypto.py:82). The security-critical hardening is `_reject_weak_public_key` (crypto.py:65), called by `load_public_key` (crypto.py:76) BEFORE any verify:
- **Non-canonical y ≥ p** is rejected (crypto.py:69) — pyca preserves a non-canonical y verbatim, so one point would have several byte encodings (key-identity ambiguity).
- **Low-order points** (the libsodium `ge25519_has_small_order` blocklist, crypto.py:54-62) are rejected, sign-bit-agnostically (`& 0x7f`, crypto.py:72). A low-order key admits a KEYLESS forgery (R=identity, S=0 verifies for any message), so barring it closes a trust-root-poisoning forgery.

Failure mode: malformed/weak material raises `IntegrityError`; a merely-invalid signature returns `False` (crypto.py:89). This is the I2 weak-key fix and it is reused by delegation, transparency, and the keystore.

### m-of-n threshold verification and the quorum-collapse caveat

`verify_threshold` (crypto.py:101) counts DISTINCT trust-root authorizers with a valid signature and compares to `trust_root.threshold`; it de-dupes by `key_id` (crypto.py:107) and returns a frozen `ThresholdResult`. `TrustRoot` (models.py:29) rejects duplicate `key_id`s and a threshold exceeding the authorizer count (models.py:36-42), but **deliberately does NOT reject duplicate PUBLIC KEYS** under distinct ids (models.py:43-50) — a documented footgun the witness subsystem intentionally exploits; consumers for whom a collapsed quorum is unacceptable re-check at their own layer (delegation and destruction do; see below).

### Canonical bytes + domain separation

`canonical.py` gives deterministic `canonical_json` (sorted keys, compact separators, canonical.py:17) and `evidence_signing_bytes` = `b"crucible-evidence-v1\x00" + canonical_json(payload)` (canonical.py:33-35). The domain tag means a signature over one artifact class can never replay as another. **SIX** distinct domain prefixes are catalogued in `spine_domains.DOMAIN_TAGS` (spine_domains.py:62-69): `evidence`, `floor`, `witness-roster`, `delegation`, `transparency`, `destruction`. (The draft's "seven" is wrong — the dict literal has six entries and lists six names. Segments not listed there sign bare sha256 hex or bare `canonical_json`, kept apart by input-shape disjointness rather than a tag — a documented, per-purpose-tag-is-the-natural-v2-hardening limit, spine_domains.py:56-61.)

### The tamper-evident spine chain + signed anti-rollback head

`chain.py` hashes each `ChainEntry` over `(seq, prev_hash, cert_digest)` (chain.py:15-16) and links them; `verify_chain` (chain.py:41) detects deletion/reorder (prev_hash mismatch), tampering (entry_hash mismatch), and seq gaps. `SignedChainHead` (models.py:63) anchors the log with a monotonic `last_seq`; `verify_head` (chain.py:78) re-derives the chain tip, checks `entry_count == base_count + len(entries)` (absolute count, prune-invariant, chain.py:88), verifies the owner threshold signature over the version-conditional `_head_payload` (chain.py:55-65 — a v1 head drops the v2 cold-archive fields so signing bytes stay byte-identical to a pre-v2 head), and enforces a `prev_highwater` rollback floor (chain.py:93). This whole file is vendored verbatim from CRUCIBLE so SIGIL owns its integrity primitives with zero offense-engine dependency (chain.py:1-6).

### Durable external anti-rollback floor

`apps/sigil/sigil/spine/floor.py` is a second, out-of-band witness at `~/.sigil/floor.json` (0600) OUTSIDE `spine/` so a routine `--reset`/rmtree cannot lower it (floor.py:3-6). It catches a stale-but-validly-signed head replay that the in-band signature alone cannot (floor.py:8-13). `check_floor` (floor.py:168) rejects a head whose absolute `entry_count`/`last_seq`/`base_seq`/`base_count` regress or whose v2 meta-chain link breaks (floor.py:175-197). It only ADDS rejections (checked after the in-band signature), so absent/satisfied it is byte-identical to the pre-floor spine (floor.py:12-13). **Label — conditional signature:** the floor's `sig`/`pubkey` are OPTIONAL (floor.py:73-78); it is owner-signed over tag `b"sigil-floor-v1\x00"` ONLY when an owner key is threaded through the write path (`_sign_floor`, floor.py:89,100-104), and `verify_floor_signature` (floor.py:107) ACCEPTS a legacy unsigned floor (returns `True`, warn-once) — byte-identical to the pre-signing spine — while a tampered SIGNED floor fails closed (floor.py:122-136). ### Keys-at-rest: sealing, TPM-sealed KEK, vault, keystore

`vigil_core/sealing.py` is the AEAD "sealed box": `seal`/`unseal` with ChaCha20-Poly1305 (sealing.py:63,76), a fresh 96-bit nonce per seal, and domain+context binding into the AAD (sealing.py:51-55,70-73) so a blob sealed as an owner key can't open as an operator key. Both envs use the same vault (sovereign owner key in `governor/identity.py:owner_keypair`, identity.py:27-38; offense operator/spine keys), so the two-env boundary is unaffected.

### Field-level spine payload encryption (previously undocumented)

`apps/sigil/sigil/spine/envelope.py` seals spine record payloads at rest PER FIELD, not per record, because a payload mixes keyless governance METADATA (`decision`/`tier`/`usage`/`signal`) with sensitive human CONTENT in one dict (envelope.py:1-8). `seal_payload` (envelope.py:102) encrypts only the VALUES of the fields in `CONTENT_FIELDS` (`text`/`quote`/`body`/`tool_input`/`vision_reading_advisory`/… envelope.py:61-65), leaving all metadata plaintext, and binds each ciphertext to `(scope, seq, field)` as AAD (envelope.py:73-75,112) so a sealed value can't be transplanted. The offense sandbox's only exit is fenced by two enforcement layers plus Docker topology.

**`gateway/vigil_gateway/proxy.py`** is the L7 policy that understands hostnames and defeats DNS rebinding. **`gateway/vigil_gateway/docker.py`** pins the sandbox onto an `internal: true` network with no default route out except through the gateway container (docker.py:14-19,62-67); the gateway container itself runs `cap_drop: ALL`, `no-new-privileges`, `read_only` (docker.py:77-81). The sandbox is pinned via Strix's existing `STRIX_DOCKER_SANDBOX_NETWORK` env (no Strix change, docker.py:21-23,48-50), and **`NET_ADMIN` is dropped** so the sandbox cannot rewrite its own netfilter/routing, keeping only opt-in `NET_RAW` for SYN scanning (docker.py:22-25) — so unsetting the in-sandbox proxy env buys the agent nothing, the packets are dropped at the host.

### Attestation interface + software/TPM fallback — SoftwareAttestationProvider BUILT; SEV-SNP/TDX hardware-gated stubs

`engine/crucible/framework/v2/attest/provider.py` turns a payload into a signed `AttestationQuote` and can `verify` it.

- **`EmbeddedGraphStore` — BUILT default, no external DB** (`store.py:199-263`). Each partition is one canonical JSON document at `<base_dir>/<partition>.json`. `project_from_spine(events, *, partition="default")` (`store.py:220-238`) writes it **atomically** (unique `mkstemp` temp + `os.replace`) so a crash mid-write never leaves a torn partition; the base dir is `chmod 0o700` and each file `0o600` (`store.py:213, 229`). Reads (`nodes`/`edges`, `store.py:249-253`) are pure file reads that return `{"nodes":[], "edges":[]}` on any `OSError`/`ValueError`/non-dict data (`store.py:240-247`). `partitions()` lists `*.json` stems (`store.py:255-256`); `drop_partition` unlinks a rebuildable projection file and **never touches the spine** (`store.py:258-263`). Partition ids are sanitized (`_safe_partition`, `store.py:179-187`) — alnum + `-_.` only, no traversal/control chars, bounded to `_MAX_PARTITION=128` (`store.py:50`).
- **`Neo4jGraphStore` — SCAFFOLD (infra-gated) STUB, every method raises** (`store.py:266-297`). `__init__` **raises `NotImplementedError`** ("infra-gated: Neo4jGraphStore requires a running Neo4j service and the `neo4j` driver…", `store.py:283-288`); `project_from_spine`/`nodes`/`edges` each raise the same infra-gated error (`store.py:290-297`). It exists so a future swap is a one-line backend change reusing `project_events` verbatim. Its activation runbook (provision Neo4j, `pip install neo4j`, implement idempotent MERGE Cypher scoped by a per-partition label, `drop_partition` = `MATCH (n:` + backtick-`part_<partition>`-backtick + `) DETACH DELETE n`) is in the class docstring (`store.py:274-281`), which explicitly notes the one-way invariant stays unchanged.
- **THE ONE-WAY INVARIANT (docstring `store.py:12-25`, load-bearing):** `project_from_spine` is a pure, derived, one-way projection — same events in → byte-identical partition out. **Nothing produced here is ever read back into a tier, grant, authorization, or FACT.** The `GraphStore` Protocol (`store.py:155-174`) and `_BaseGraphStore` (`store.py:176-197`) deliberately have **no** promote/grant/tier/authorize method — a projection that could feed a decision would be a covert channel around the oracle. Partitions are per-session (default `"default"`), mirroring `console/sessions.py`'s per-session model, and dropping one loses no authority. `open_graph_store(base_dir)` (`store.py:300-302`) is the factory returning the embedded backend that call sites should use today.

### Live-key Claude think-step (VIGIL-LIVE §12 WS1e) — opt-in / key-gated; keyless falls back to replay

`integration/vigil_integration/live/think_claude.py` binds the F2 ReAct think-step to a real Claude Messages call while changing nothing about the sovereign contract: a think step only ever emits a **non-authoritative proposal**. (The module self-labels "VIGIL-LIVE, §12 WS1e" at `think_claude.py:2` — it is BUILT, not a deferred scaffold, and has no `DEFERRED-INFRA.md` runbook.)

- **`think(state, prompt_ctx, *, client, replay, api_key, model, max_tokens)` — the public entry** (`think_claude.py:404-467`). Backend selection is fail-closed / deny-by-default at every step (`think_claude.py:444-467`):
  1. An injected `client` (a test fake or a caller-built real client) wins; its own auth is used and the `api_key` arg is ignored (`think_claude.py:445-446`).
  2. Else a resolvable key (`api_key` arg, else `ANTHROPIC_API_KEY` via `_resolve_key`, `think_claude.py:358-366`) → build a real `anthropic.Anthropic` client via `_build_live_client` (`think_claude.py:369-382`, lazy SDK import) and go live; if the client can't be built, return the safest action (`think_claude.py:449-457`).
  3. Else an injected `replay` (a scripted `LLMDecision` sequence, typically `ReplayThinker`) → keyless-live via `_think_via_replay` (`think_claude.py:459-461`).
  4. Else nothing wired → the safest `ASK_USER` action (`think_claude.py:463-467`).
- **The three-stage pipeline (docstring `think_claude.py:5-31`):**
  1. **Frame untrusted context.** Every attacker-influenceable input (the `prompt_ctx` and the prior-action digest from the execution trace) is wrapped via `safety.prompt_safety.wrap_untrusted` / `wrap_untrusted_inline` with the standing `UNTRUSTED_OUTPUT_GUIDANCE` directive (`_build_messages`, `think_claude.py:195-227`; `_recent_actions_digest`, `think_claude.py:171-192`). Secrets in prior-action args are masked first via the F3 `tools.redact_tool_args` (`think_claude.py:53, 188`) so a credential never enters the prompt or a span/log. Context is bounded (`_MAX_CTX_CHARS=200_000`, `think_claude.py:103`; last `_RECENT_ACTIONS=3` trace entries, `think_claude.py:105`).
  2. **Ask for ONE structured decision.** One Messages call via `_think_via_client` (`think_claude.py:287-312`). For current-generation models it sends `thinking:{type:"adaptive"}` (`_thinking_kwargs`, `think_claude.py:88-98`) plus the UI-chosen effort `output_config.effort` (`_effort_kwargs`, `think_claude.py:77-85`), and STREAMS via `.messages.stream(...).get_final_message()` — falling back to `.messages.create` for a client without `.messages.stream` (`_invoke`, `think_claude.py:272-284`). Thinking blocks in the reply are ignored; only text blocks are read (`_extract_text`, `think_claude.py:241-264`).
  3. **Parse FAIL-CLOSED.** Raw model text → `agent.react.parse_decision`, which downgrades malformed/garbage/oversized responses to the safest inert `ASK_USER` action (`_safest`, `think_claude.py:115-119`) — never an action-bearing edge from garbage, never an authorization (docstring `think_claude.py:20-25`). Response text is bounded to `_MAX_RESPONSE_CHARS=400_000` before the parser (`think_claude.py:104, 308-309`).
- **Model / effort env bridge (previously undocumented vs AS-BUILT):** `resolve_model(explicit)` (`think_claude.py:390-401`) picks an explicit non-empty value, else the UI-picker env (`CRUCIBLE_ANTHROPIC_MODEL` / `SIGIL_LLM_MODEL`, `_MODEL_ENV_VARS`, `think_claude.py:65`), else `DEFAULT_MODEL="claude-opus-5"` (`think_claude.py:58`). `_effort_kwargs` reads `CRUCIBLE_EFFORT` and only applies it for models whose prefix is in `_CURRENT_MODEL_PREFIXES` (`think_claude.py:71-74`), since current-gen models reject `temperature`/`budget_tokens`. This is the seam that makes a UI model/effort choice actually take effect on `vigil engage`'s think step — reading env only, with no import of the sovereign Settings module (the two-env boundary holds, comment `think_claude.py:62-64`).
- **`ReplayThinker` — keyless-live backend** (`think_claude.py:470-497`). A stateful callable seeded with a sequence of `LLMDecision` / JSON strings / dicts (coerced fail-closed via `_coerce_decision`, `think_claude.py:315-331`); each call yields the next scripted decision, and once exhausted yields the safest `ASK_USER` (`think_claude.py:485-490`). Deterministic, no wallclock/RNG — safe to snapshot alongside the spine (docstring `think_claude.py:476`).
- **Secret-free / never-raises (docstring `think_claude.py:33-36`, and `think_claude.py:414-431`):** the API key is only ever forwarded to the SDK constructor — never logged (exception paths log `type(exc).__name__` only, `think_claude.py:304-306, 380-382`), never spined, never in the inspectable request. `think` never raises; it always returns an `LLMDecision`, which is a **proposal only** — it must still clear `agent.react.authorize_edge` (the conjunctive gate) before anything runs, and the oracle still judges the bytes, so a hallucinated context can never mint a FACT.

### Live telemetry-collector sidecar (VIGIL G2) — opt-in, pure one-way projection, fail-soft

`integration/vigil_integration/telemetry.py` materializes a continuously-updated metrics snapshot from the signed spine. The module self-labels "VIGIL G2" (`telemetry.py:1`); note it is a **BUILT** collector — there is **no G2 section in `docs/DEFERRED-INFRA.md`**, so it is not a deferred scaffold with an activation runbook (a doc gap the draft's intro overstated).

- **`collect_snapshot(bb, *, engagements=None, generated_at=None)` — the PURE projection** (`telemetry.py:57-91`). Given a blackboard `bb` exposing `replay(engagement=, since_id=)`, it folds each event via `_fold_event` (`telemetry.py:38-54`) into per-engagement metrics and a running total. Counters (`_blank_metrics`, `telemetry.py:33-35`): `events`, `facts`, `leads`, `refusals`, `tool_calls`, `messages`, `findings`, a `by_kind` histogram, and `last_event_id`. The **facts-vs-leads split is oracle-grounded**: a `finding` event with truthy `payload["verified_by_oracle"]` counts as a FACT, else a LEAD (`telemetry.py:43-48`); `refusal` → refusals; `action`/`tool_call` (`_TOOL_KINDS`, `telemetry.py:30`) → tool_calls; `agent_message` → messages. It is **deterministic** — no wallclock/RNG (an optional `generated_at` is the only injected stamp, `telemetry.py:88-90`) — and **total**: an unreadable engagement is caught and contributes an empty section, never a traceback (`telemetry.py:69-71`). Slugs default to every slug on the spine via `_all_engagement_slugs` (a read-only `SELECT slug FROM bb_engagements ORDER BY id`, returning `[]` on any error, `telemetry.py:94-104`).
- **`run_collector` / `main` — the sidecar** (`telemetry.py:125-167`). The `vigil telemetry` / `vigil up --with-telemetry` loop: every `--interval` seconds (default 15, floored to 1.0 via `max(1.0, float(interval))` `telemetry.py:156`) it opens the blackboard, writes a snapshot to `--out`, and closes — or `--once`. `now_fn`/`sleep_fn`/`open_fn` are injectable for tests. **Fail-soft:** a closed/absent spine writes an honest empty snapshot with a `"note"` (`telemetry.py:138-143`); a collection error writes an empty snapshot noting the error type (`telemetry.py:141-143`); a write `OSError` is logged to stderr and retried next tick (`telemetry.py:144-147`). `_write_snapshot` writes atomically (tmp + `os.replace`) so a reader never sees a half-written file (`telemetry.py:117-122`).
- **One-way invariant + import-cleanliness (docstring `telemetry.py:1-17`):** a pure one-way projection of the spine — nothing is read back into it, no tier/grant is derived from it, so it can only reflect what the oracle+gate already recorded; it never mints a fact and never widens anything. It is stdlib-only and lazy-imports the framework blackboard (`_open_blackboard`, `telemetry.py:107-114`, returns `None` on any import error), so importing it in the sovereign env stays clean — the two-env boundary holds.
